# AArch64 register-offset memory lifting

The scalar A64 decoder supports integer register-offset `LDR`, `STR`, `LDRB`/`STRB`, `LDRH`/`STRH`, and `LDRSW` forms. It records the memory width, base and index registers, the encoded element-size shift, and the 64-bit sign-extending destination effect of `LDRSW`. The supported index options are UXTX/LSL, UXTW, SXTX, and SXTW; signed word indices remain explicitly sign-extended in the lifted address expression. It also decodes signed-imm9 pre-index and post-index integer `LDR`/`STR`/`LDRB`/`STRB`/`LDRH`/`STRH` forms. Pre-index accesses use the adjusted address and write the adjusted base; post-index accesses use the old base and then write the adjusted base, as specified by [Arm's A64 architecture guide](https://developer.arm.com/-/media/Arm%20Developer%20Community/PDF/Learn%20the%20Architecture/Armv8-A%20Instruction%20Set%20Architecture.pdf?revision=ebf53406-04fd-4c67-a485-1b329febfb3e). Base/destination overlap and unsupported signed-load or unprivileged encodings are rejected.

The common decompiler IR represents the decoded register-offset address as an indexed `MemoryValue`, so those loads and stores participate in existing memory SSA and pseudocode formatting. For example, `ldr x0, [x1, x2, lsl #3]` lifts to `x0 = *[(x1 + (x2 << 3))]`, and `str x0, [x1, w2, sxtw #3]` retains `sxtw(w2)` in its address. The shift is the access-size scale encoded by the instruction, not a guessed array type. Pre/post-index single-register operations remain explicit memory intrinsics that record the effective memory address, new base value, memory direction, and output registers without collapsing the ordering into one ordinary assignment.

This is integer scalar coverage only. `LDRSW` support is limited to the register-offset form; other signed-extending loads, SIMD/FP accesses, unsigned-scaled immediate writeback forms, unprivileged forms, and prefetch instructions are outside this decoder subset.

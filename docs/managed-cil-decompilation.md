# Managed CIL decompilation

## Indirect pointer memory subset

The lifter models scalar `ldind.*` and `stind.*` families as explicit memory operations. Loads consume one address and emit a read intrinsic with a typed result: signed/unsigned 8-, 16-, and 32-bit loads use the CIL evaluation-stack I4 category, 64-bit loads use I8, `r4`/`r8` use their floating widths, `ref` yields a managed reference, and native `i` retains an unknown target width. Stores consume address and value and emit write intrinsics. `ldobj`, `stobj`, `initobj`, and `cpobj` validate and retain TypeDef, TypeRef, or TypeSpec tokens and emit explicit memory intrinsics with the correct stack effects. `ldobj` keeps an unknown result type; `cpobj` uses an unknown memory effect because the token's size and alias behavior are unresolved. `cpblk` and `initblk` preserve destination, source/fill value, and dynamic size operands; `cpblk` has an unknown read/write effect and `initblk` a write effect. Object and block operations mark the decompilation incomplete and add a diagnostic because aggregate sizes, exact value types, dynamic extent, and alias behavior are unresolved. Stack underflow and `max_stack` violations remain malformed errors. The lifter does not prove that an address is a managed byref, validate a stored value against the pointed-to type, resolve aggregate layouts, evaluate memory, or infer alias relationships.

## Field access subset

`ldfld`, `stfld`, `ldsfld`, and `stsfld` are lifted when their operand is an in-module FieldDef token with a parsed field signature. The resolver retains declaring type/name, signature, flags, and token. The lifter verifies static-vs-instance opcode use against the FieldDef static flag, carries the object expression for instance access, types loads when the signature maps to a supported `ValueType`, and emits explicit read/write memory-effect intrinsics. Field tokens are included in `referenced_tokens`. Field address operations (`ldflda`/`ldsflda`) remain unsupported. MemberRef fields, unresolved signatures and external identities are unsupported explicitly; they are never guessed. This remains a bounded lifter rather than CLR verification, so receiver assignability and store value compatibility are not proven.

`hexlab::decompiler::decompile_managed_method` converts a decoded `ManagedMethodAnalysis` into the common lifted-function IR and structured C-like pseudocode. It partitions IL at branch leaders, builds basic blocks and branch/fallthrough edges, simulates the evaluation stack within each block, and represents arguments, locals, fixed-width constants, arithmetic, comparisons, calls, and returns as IR expressions/statements. Method and call metadata tokens remain in the output's `referenced_tokens` list and in call names.

The floating-point slice preserves `ldc.r4`/`ldc.r8` constants as exact IEEE bit patterns, types floating stack values at 32 or 64 bits, and lifts `conv.r4`, `conv.r8`, and `conv.r.un` with explicit integer-to-float or float-width conversion operations. Floating add/subtract/multiply/divide, remainder, equality, ordered comparisons, and unordered `cgt.un`/`clt.un` and comparison branches retain floating types and unordered-NaN behavior. Exact literal bit patterns render as `bitcast_f32`/`bitcast_f64`; floating remainder and unordered predicates render as explicit operations. Unsupported or mismatched floating stack types stop lifting rather than being coerced to integers. Native-width and checked conversions remain outside this slice.

Call stack effects use decoded `ManagedCallSignature` metadata keyed by token, with an explicit map available to override metadata resolution. The decompilation result preserves the method's declaring-type and method generic parameter records, including flags and constraint tokens. Call arguments and results inherit supported types from resolved metadata signatures. Closed generic TypeSpec parents and MethodSpec method arguments are substituted for call typing; open generic owners and unresolved substitutions remain unknown, and the common IR does not print complete generic source types. Invalid instruction boundaries, stack underflow, and excess values at `ret` fail with `malformed`. Exception-handling sections are retained within the bounded behavior described below; unrelated extra method-data sections are rejected as unsupported.

Method signatures now retain their decoded return and parameter signature trees. `ELEMENT_TYPE_VAR` and `ELEMENT_TYPE_MVAR` nodes carry the compressed generic parameter index; generic instances retain their coded type identity, class/value marker, and ordered type arguments. For a `MethodSpec` token, `method_spec_arguments` retains each instantiation type, and that token's resolved call signature preserves the base method's signature and generic arity. The CIL lifter uses the signature for stack effects and supported call typing. MethodSpec arguments substitute MVAR nodes and closed generic TypeSpec parent arguments substitute VAR nodes for call argument/result categories. TypeDefOrRef coded indexes are preserved alongside resolved tokens and names when in-image metadata provides them. Constraint rows likewise remain raw metadata tokens; no constraint semantics are inferred.

Catch clauses resolve in-image TypeDef and TypeRef tokens to fully qualified names for lifted predicates and handler markers. The original token remains in each predicate and in `referenced_tokens`. TypeSpec names and absent tokens remain unresolved. This does not bind external assembly identities or evaluate CLR catch assignability.

This is a bounded semantic slice, not a CLR verifier. It supports argument/local loads and stores, integer and floating constants, `ldnull`, metadata-resolved `ldstr` constants, `dup`, `pop`, integer and floating arithmetic, comparisons, fixed-width unchecked integer and floating conversions, basic conditional/unconditional branches, signature-resolved `call`, `callvirt`, and `newobj`, `ret`, and `throw`. The array subset includes `newarr`, `ldlen`, `ldelema`, and fixed-width `ldelem.*`/`stelem.*` variants. Allocation, length, element-address, element-load, and element-store operations are explicit intrinsics with memory effects; primitive load result widths are preserved. Native-width integer and array-length values keep an unknown bit width because the method view has no target pointer-width field. `ldstr` values retain their original token and render as escaped string literals; see [Managed CIL user strings](managed-cil-user-strings.md). Integer conversions preserve their I4/I8 evaluation-stack result width. Narrow integer conversions retain an explicit truncate followed by sign or zero extension when the input type is known; when it is unknown or non-integer, the IR retains a named `cil_conv_i1`/`cil_conv_u1`-style operation instead of inventing source semantics. Floating constants preserve their raw IEEE bits, and `conv.r4`, `conv.r8`, and `conv.r.un` preserve explicit source/result widths. Unordered comparisons use explicit unordered predicates so NaN behavior is not lost. `leave` clears the evaluation stack and, when exiting nested finally-protected try regions, follows explicit continuation IDs through applicable finally handlers in inner-to-outer order before reaching its original target. The lifted CFG contains the corresponding `endfinally` dispatch edges. A leave does not run a finally whose try region contains its target. Catch, filter, and finally region bounds become block boundaries and receive typed intrinsic markers; catch and filter entries begin with an `exception` value. Each instruction in a protected try has a conservative exceptional edge to a synthetic ordered dispatcher, kept separate from ordinary stack flow; this over-approximates throwability. Exceptional successors enter synthetic dispatch blocks that preserve catch-clause order with opaque runtime type-match predicates and route through applicable nested finally handlers. Filter evaluation retains the original exception search: `endfilter` routes by its result, while an explicit throw or conservatively possible exception in filter code resets the result to false and resumes ordered search by the active filter continuation. Nested exception regions and `rethrow` inside filters remain unsupported. `rethrow` elsewhere is modeled only inside a catch or filter handler. CLR type assignability and exact throwability remain runtime-dependent, so protected instructions still use conservative possible-throw edges; fault clauses run only on exceptional unwind, and this CFG is not a CLR runtime simulator. Ambiguous overlapping finally regions remain unsupported.

Stack values may flow across modeled block edges, including loop backedges. A bounded worklist first propagates evaluation-stack depth and exact IR `ValueType` shapes through the CFG; each analyzed block shape is established once, while later backedge inputs must match it exactly. Conflicting depth or types are malformed. The emission pass preassigns block-edge stack values and creates explicit SSA phis at multi-predecessor joins, including loop headers, so forward/backedge inputs need no speculative expressions. A 2,000,000-transfer budget, 1,000,000-edge bound, 4,000,000 aggregate stack-cell bound, declared `max_stack` (or a conservative 1,024-entry bound when unavailable), and the 256-slot virtual-register limit keep this analysis bounded. Unreachable components are seeded with an empty stack for conservative local analysis; unsupported instructions terminate stack propagation rather than inventing values. `switch` decodes its bounded target table, pops one selector, creates case leaders and dispatch edges, and preserves ordered zero-based case values plus the fallthrough default in the common switch-dispatch IR. It does not yet resolve actual argument/local types or names, token-typed `ldelem`/`stelem`, MemberRef fields, field addresses, native-width/checked conversions, generics, or runtime-specific instructions. Unknown and known-but-unsupported opcodes are retained as explicit unsupported IR markers and mark the result incomplete; unsupported stack effects return an error instead of producing guessed pseudocode. Basic blocks are limited to 100,000 and instructions to one million, in addition to the loader's per-method IL bound.

Validation: `tests/decompiler/cil_decompiler_tests.cpp` checks local/argument flow, integer arithmetic, conditional CFG recovery and returns, compatible conditional-path stack merging and phi inputs, malformed depth/type merges, token-preserving signature-resolved calls, malformed stack underflow, unknown opcodes, and missing call-signature rejection.

# Static Mach-O linking

`hexlab_cli archive link-macho <archive> --root-object <object.o> --entry <symbol> --output <program>` selects regular Mach-O archive members to a fixed point and emits a static x86-64 or ARM64 `MH_EXECUTE`. The archive member scanner accepts thin little-endian 64-bit x86-64 and ARM64 `MH_OBJECT` members, so ARM64 archive selection reaches the same checked relocation path as direct ARM64 object linking. The link path uses the same bounded archive selector as the ELF and COFF workflows. Every selected object must have the same architecture. It resolves archive providers by external symbol name, prefers a strong definition over a weak one, rejects duplicate strong definitions, and fails before output when strong references remain unresolved.

Both modes require little-endian 64-bit `MH_OBJECT` files with `__TEXT,__text`, initialized `__DATA,__data`, and optional zero-fill `__DATA,__bss`. Read-only input contributions may use `__TEXT,__const` or `__DATA_CONST,__const` (`S_REGULAR`), `__cstring` (`S_CSTRING_LITERALS`), `__literal4` (`S_4BYTE_LITERALS`), `__literal8` (`S_8BYTE_LITERALS`), or `__literal16` (`S_16BYTE_LITERALS`). `__DATA_CONST,__const` is folded into the executable's read-only output mapping; relocations are applied before the image is emitted, so its initialized pointer constants are resolved without requiring runtime rebasing. C-string sections must end in NUL, and literal section sizes must contain whole elements. Each read-only contribution keeps its source section ordinal and aligned output offset for symbols and relocations, then merges into the output's read-only `__const` section. The output is an executable, so literal-pool section types need not be preserved for another relocatable link. Contributions are merged in input object/section order. Symbols and supported relocations can target all merged sections; relocations may be stored in any file-backed merged section. Entry symbols must be defined inside `__text`.

The x86-64 path applies `UNSIGNED`, `SIGNED`, `BRANCH`, `SIGNED_1`, `SIGNED_2`, and `SIGNED_4` relocations. The ARM64 path applies `UNSIGNED` 32/64-bit relocations, `BRANCH26`, `PAGE21`, and `PAGEOFF12`. It also supports `GOT_LOAD_PAGE21`, `GOT_LOAD_PAGEOFF12`, and the 4-byte PC-relative `POINTER_TO_GOT` form when each external symbol resolves to a definition in one of the linker's supported output sections. GOT slots hold the resolved symbol address plus the signed 24-bit `ADDEND` (for GOT page relocations); identical resolved section/value/addend tuples share one slot. The bounded GOT is synthesized into the read-only `__CONST` mapping because all symbols are resolved before output and no runtime rebasing is needed. `GOT_LOAD_PAGEOFF12` is limited to zero-immediate 64-bit integer `LDR`; its paired `ADRP` and `LDR` relocations must resolve to the same slot. `POINTER_TO_GOT` supports only a 4-byte signed PC-relative field, whose encoded addend is preserved and range-checked. ARM64 `ADDEND` records are accepted only as signed 24-bit companions to same-offset `PAGE21`, `PAGEOFF12`, `GOT_LOAD_PAGE21`, or `GOT_LOAD_PAGEOFF12` records. Instruction immediates must be zero before relocation; ordinary `PAGEOFF12` recognizes ADD-immediate and scaled load/store instruction forms and validates access alignment. Instruction relocations are range-checked and branch veneers are not synthesized. ARM64 inputs use 16 KiB output segment alignment and an ARM_THREAD_STATE64 `LC_UNIXTHREAD` entry state.

Relocation type values were checked against [LLVM's Mach-O definitions](https://github.com/llvm/llvm-project/blob/main/llvm/include/llvm/BinaryFormat/MachO.h), and instruction relocation formulas were cross-checked against [lld's ARM64 Mach-O backend](https://llvm.googlesource.com/llvm-project/lld/+/cd6be8c3a677bfa0f57a167dff24b02724df54ca/MachO/Arch/ARM64.cpp). No upstream implementation code was copied.

Output contains RX `__TEXT`, read-only `__CONST`, and RW `__DATA` segments; `__DATA` contains merged `__data`, zero-fill `__bss`, and a distinct zero-fill stack section. A bounded external symbol/string table and architecture-specific `LC_UNIXTHREAD` state are emitted. The image has no dynamic loader dependency.

Other allocated sections, including `__AUTH_CONST` and `__DATA_CONST` sections other than regular `__const`, BSS-stored relocations, TLV/subtractor/section-difference relocations, scattered relocations, weak unresolved imports, common symbols, mixed architectures, and branch veneers are not implemented. ARM64 TLVP, authenticated-pointer, subtractor, and addend-with-branch relocations remain unsupported. GOT references to unresolved/dynamic symbols and the absolute 8-byte `POINTER_TO_GOT` form are rejected. Unsupported forms are rejected instead of being copied with unresolved fields. Bounded `__eh_frame` CIE/FDE contributions are preserved for x86-64 and ARM64 with the relocation subset described in [Mach-O linker unwind metadata](macho-link-eh-frame.md); compact-unwind tables are not synthesized. 32-bit, big-endian, universal input objects and libraries, and dynamic linking remain outside this link path.

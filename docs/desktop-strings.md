# Desktop string browser

The Metadata notebook's Strings page filters discovered strings by preview text, mapped address or file offset, and encoding. The split view shows the selected string's incoming references and supports bounded paging; activating a string navigates to its data, while activating a reference navigates to its source.

Incoming references use the current project `ReferenceIndex`. Mapped strings query the file range together with virtual aliases; strings without a mapped address query the file range directly. Results are paged in groups of 128. Stale and pending analysis does not show old reference rows, and incomplete analysis is labeled. Standalone documents without a project reference index still support string filtering and navigation, but cannot browse references.

**Export filtered CSV...** writes the current filtered string set, independent of selection. **Export all CSV...** writes every discovered string and ignores the current filter. Each CSV row contains the string address (when mapped), file offset, encoding, byte and character lengths, termination state, preview text, and an incoming-reference source/kind/operand when available. Strings with no incoming references still receive a row. Strings with references receive one row per reference, so a string with multiple sources is repeated. Both exports walk the same mapped-alias-aware index queries in bounded pages of 128 and write incrementally through protected file publication; neither accumulates the full export in memory. Standalone, stale, pending, file-only, or otherwise unavailable reference data is represented in `reference_status` instead of being presented as an empty reference set. Incomplete string or reference analysis is labeled partial, including strings with no indexed incoming references. CSV fields are quoted and quote characters escaped; output is UTF-8 with CRLF records.

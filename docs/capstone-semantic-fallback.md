# Capstone fallback facts

The Capstone fallback preserves Capstone's mnemonic and operand text and the original instruction bytes. Its opcode remains `Opcode::opaque`; no fallback instruction is treated as liftable merely because Capstone decoded it.

When Capstone detail is available, control groups are mapped for enabled fallback modes: calls, returns/interrupt returns, traps, and jumps. A call, return, or trap group takes precedence if Capstone also marks an instruction as a jump. Conditional jumps are recognized for x86 Jcc/loop mnemonics, A64 `B.cond`/`CBZ`/`CBNZ`/`TBZ`/`TBNZ`, A32/Thumb conditional `B` and `CBZ`/`CBNZ`, RISC-V integer and compressed compare branches, selected classic MIPS branches, PowerPC condition-code/CTR branches, and MOS6502 conditional branches. Conditional calls remain represented as calls because the shared flow enum has no conditional-call case.

For x86 16-, 32-, and 64-bit modes, the fallback converts register, immediate, and memory operands. Register operands are mapped for the general purpose register bank, IP, flags, segments, XMM, and YMM when the Capstone name maps unambiguously. Memory read/write flags follow Capstone operand access bits; operands with no access bits are omitted. Address base/index reads come from the decoded address expression. A direct target is retained for an immediate operand of a call or branch.

A64 and A32/Thumb use Capstone's per-operand access bits for register, immediate, and memory operands. For supported A64 and A32/Thumb direct branches, Capstone detail contains the absolute target; the ARM printer applies the architectural PC bias and Thumb `BLX` alignment before recording the operand. Unsupported interworking state transitions remain unresolved by the fallback. RISC-V converts register/immediate operands when register access can be established and represents memory operands as address-only; supported direct branch/JAL target offsets are added to the instruction PC with checked address width and alignment. `JAL x0` is an unconditional jump. MIPS and PowerPC convert register/immediate operands when generic register access establishes their roles, and likewise retain memory forms as address-only. Selected classic MIPS direct branches/jumps retain Capstone's absolute target and one delay slot; Release 6 compact and branch-likely forms receive no direct target or delay-slot fact from this extension. Supported PowerPC direct `B`/`BC` families retain the absolute target produced by Capstone's printer. MIPS HI/LO/FCSR and PowerPC CR-field/LR/CTR/XER names map to project register banks when their identity is unambiguous. Register read/write sets use `cs_regs_access` only when every register maps to a known project bank; one unmappable implicit register suppresses both sets rather than emitting partial data.

For MOS6502, Capstone detail now exposes typed 8-bit register/immediate operands and 16-bit-address memory operands when the register roles are available. Indexed zero-page/absolute forms retain their X/Y index register; unindexed zero-page, absolute, relative-branch and zero-page-relative operands receive resolved addresses from Capstone detail. Memory operands remain address-only because Capstone's MOS65XX detail has no per-operand access bits. Absolute JMP/JSR targets are retained; indirect JMP is not converted to a direct target. Relative branch destinations are taken only from Capstone's decoded target operand, never parsed from display text. BCC/BCS/BEQ/BMI/BNE/BPL/BVC/BVS and BBR/BBS are classified conditional, while BRA/BRL are unconditional jumps.

Capstone detail may omit access information in diet builds; access-dependent operands are omitted in that case. Unsupported register names and operand types are omitted. No opcode semantics, stack effects, branch-likely annul rules, precise condition expressions, or architecture-specific state transitions are inferred here.

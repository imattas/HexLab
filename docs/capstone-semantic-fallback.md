# Capstone fallback facts

The Capstone fallback preserves Capstone's mnemonic and operand text and the original instruction bytes. Its opcode remains `Opcode::opaque`; no fallback instruction is treated as liftable merely because Capstone decoded it.

When Capstone detail is available, control groups are mapped for enabled fallback modes: calls, returns/interrupt returns, traps, and jumps. Conditional-branch identity is also checked against architecture instruction IDs and detail, so it is retained even when a backend omits its generic jump group. Calls, returns, and traps keep precedence. The fallback recognizes x86 Jcc/loop mnemonics, A64 `B.cond`/`CBZ`/`CBNZ`/`TBZ`/`TBNZ`, A32/Thumb conditional `B` and `CBZ`/`CBNZ`, RISC-V integer and compressed compare branches, classic/likely/compact MIPS compare branches and coprocessor conditions, PowerPC condition-code/CTR branches, and MOS6502 conditional branches. Conditional calls remain represented as calls because the shared flow enum has no conditional-call case.

For x86 16-, 32-, and 64-bit modes, the fallback converts register, immediate, and memory operands. Register operands are mapped for the general purpose register bank, IP, flags, segments, XMM/YMM/ZMM, and AVX-512 opmask registers K0-K7 when the Capstone name maps unambiguously. Vector registers retain their architectural width (128/256/512 bits); opmask registers use the project's 64-bit opmask bank. Memory read/write flags follow Capstone operand access bits; operands with no access bits are omitted. Address base/index reads come from the decoded address expression. A direct target is retained for an immediate operand of a call or branch.

A64 and A32/Thumb use Capstone's per-operand access bits for register, immediate, and memory operands. For supported A64 and A32/Thumb direct branches, Capstone detail contains the absolute target; the ARM printer applies the architectural PC bias and Thumb `BLX` alignment before recording the operand. Unsupported interworking state transitions remain unresolved by the fallback. RISC-V converts register/immediate operands when register access can be established and now classifies common integer/floating and compressed load/store forms by instruction ID; LR is a read, SC is a write, and the complete bundled AMO.W/AMO.D ID families report read-write memory access with 32/64-bit widths. MIPS and PowerPC likewise classify bounded common integer/floating load/store families, including selected unaligned MIPS operations and PowerPC byte-reverse/update/indexed forms; MIPS `LWU` is a 32-bit read; LL/LLD are reads. PowerPC `LWA`, `LWAUX`, and `LWAX` are 32-bit memory reads even though the loaded word is sign-extended into a 64-bit destination; load-reserve and conditional-store instructions retain their read or write direction. Full-width PowerPC vector transfers `LVX`, `LVXL`, `LXV`, and `LXVX` report 128-bit reads; `STVX`, `STVXL`, `STXV`, and `STXVX` report 128-bit writes. Element and splat vector forms are not included. These known memory operands report `read`, `write`, or `read_write` access and set the instruction memory flags. Unlisted memory forms remain `address` only, and no atomic ordering or execution behavior is inferred. Supported RISC-V direct branch/JAL target offsets are added to the instruction PC with checked address width and alignment. `JAL x0` is an unconditional jump. MIPS branch-flow classification includes ordinary, likely, compact compare, and coprocessor-condition branches, including BGEZAL/BLTZAL when Capstone does not classify them as calls; Capstone call classification retains precedence for those conditional calls. Direct targets and one delay slot are also retained for classic BGEZAL/BLTZAL forms. Other likely and compact forms remain without inferred targets or delay-slot execution facts. Supported PowerPC direct `B`/`BC` families retain the absolute target produced by Capstone's printer. CTR-only `BDNZ`/`BDZ` branches are conditional even when Capstone omits their BO/BI detail; this includes prediction, absolute-address, link, and LR-targeting aliases. Conditional link aliases retain call precedence when Capstone classifies them as calls. MIPS HI/LO/FCSR and PowerPC CR-field/LR/CTR/XER names map to project register banks when their identity is unambiguous. Register read/write sets use `cs_regs_access` only when every register maps to a known project bank; one unmappable implicit register suppresses both sets rather than emitting partial data.

For MOS6502, Capstone detail exposes typed 8-bit register/immediate operands and 16-bit-address, 8-bit-data memory operands when the register roles are available. Indexed zero-page/absolute forms retain their X/Y index register; unindexed zero-page, absolute, relative-branch and zero-page-relative operands receive resolved addresses from Capstone detail. HexLab assigns data-memory access from the decoded instruction ID: loads/ALU/compare/BIT and BBR/BBS read, STA/STX/STY/STZ write, ASL/LSR/ROL/ROR/INC/DEC/RMB/SMB/TRB/TSB read-write, and indirect JMP reads its pointer. Indirect addressing modes also set the instruction-level memory-read summary for pointer fetches, including indirect stores; a pointer operand's resolved address identifies its encoded pointer location and does not claim to resolve the final effective address. PHA/PHP/JSR/BRK report implicit stack writes; PLA/PLP/RTS/RTI report implicit stack reads, and these instructions report S read/write effects. These stack facts are instruction-level booleans and do not encode the exact page-$01 byte offsets or access widths. Relative branch target operands remain address-only, including the second operand of BBR/BBS. Other memory roles remain address-only when not covered by this table. Absolute JMP/JSR targets are retained; indirect JMP is not converted to a direct target. Relative branch destinations are taken only from Capstone's decoded target operand, never parsed from display text. BCC/BCS/BEQ/BMI/BNE/BPL/BVC/BVS and BBR/BBS are classified conditional, while BRA/BRL are unconditional jumps.

The MOS6502 fallback also supplements Capstone's implicit-register read/write
sets for common base instructions. Instruction IDs identify A/X/Y/SP dataflow,
status-register updates and branch-condition reads for arithmetic, logic,
loads/stores, compares, shifts, increments, transfers, stack operations and
conditional branches. This includes the 65C02 PHX/PHY/PLX/PLY stack operations.
Since the status register is represented as one byte, instructions that change
only selected flags report both a status read and write. These access facts do
not provide flag formulas or executable semantics.

The `hexlab_cli disassemble --json` instruction rows include `flow`, `memory_read`, `memory_write`, and `operand_access` alongside address, bytes, and formatted text. `operand_access` preserves the decoded operand order and reports `read`, `write`, `read_write`, or `address`, making conservative fallback facts inspectable without interpreting display text. Capstone detail may omit access information in diet builds; access-dependent operands are omitted in that case. Unsupported register names and operand types are omitted. No opcode semantics, exact stack addresses or widths, branch-likely annul rules, precise condition expressions, or architecture-specific state transitions are inferred here.

For A64 integer scalar transfers, `LDR`, `LDUR`, and `LDTR` plus their byte/halfword/signed variants, and `STR`, `STUR`, and `STTR` plus byte/halfword variants, retain Capstone's per-operand read/write access and report the transfer width on the memory operand. Unsigned byte/halfword forms and signed byte/halfword/word forms use their memory access width; generic word/doubleword forms take the width from a decoded W/X register. Integer `LDP`/`STP` report the combined two-register transfer width, and `LDPSW` reports 64 bits. SIMD/vector forms sharing generic LDR/STR IDs remain without an inferred data width. Writeback, ordering, and architectural effects beyond Capstone's decoded access bits are not inferred.

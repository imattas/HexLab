# WebAssembly function lifting

`lift_wasm_function` is a bounded, fail-closed scalar stack lifter. It consumes a recovered function snapshot, uses each instruction's function-relative address, and constructs typed common-IR expressions from stack constants and scalar numeric operators. It splits the flat function stream into blocks at structured-control operators, branch targets, and fallthroughs. Operand stacks are propagated across reachable CFG edges; matching stack shapes at joins become explicit `wasm_stack` phi values, including loop backedges. A function with a supported return can be represented as a common-IR `Return`.

## Supported instructions

- `nop`, `end`, `return`, `drop`
- `block` and `loop` with an empty, shorthand single-value type, or indexed numeric parameter/result signature; indexed signatures may carry up to 128 numeric parameters and results
- `if`/`else` with an empty, shorthand single-value type, or indexed numeric parameter/result signature; parameters are consumed from the condition's surrounding stack then made available in both arms, and result values join at the end; non-void results require an `else` arm
- `br` and `br_if` when their lexical label depths resolve to a block/loop/if label or the implicit function label, and the complete target stack shape is preserved; a branch to the function label rejoins at the final `end` and returns the declared results
- `br_table` with up to twelve explicit cases, when every case and default depth resolves to an explicit block/loop/if label or the implicit function label and preserves the target stack shape; this becomes a common-IR switch dispatch
- `select` on same-typed values, emitted as a typed conditional expression
- `local.get`, `local.set`, and `local.tee` for numeric MVP locals when the snapshot includes the function signature and expanded declared-local types; parameters initialize from `argN`, declared locals initialize to zero, and local values use dedicated typed pseudo-registers
- direct `call` when the target function index and signature are present in module metadata; arguments and up to 128 numeric results are type-checked, and effectful named intrinsics produce typed stack pseudo-registers for each result
- `global.get` and mutable `global.set` for numeric globals with exact combined imported/defined index, type, and mutability metadata; opaque effectful named intrinsics preserve global ordering
- `call_indirect` when the single table index and exact type index are valid and the numeric signature has up to 127 parameters and 128 results. The runtime i32 table index is preserved, and the call is marked may-trap for a bounds or type mismatch. A uniquely proven slot may inform a target hint; target resolution is not required.
- `i32.const`, `i64.const`, `f32.const`, `f64.const`
- Numeric comparisons and scalar operators in opcodes `0x45..0xa6` when the exact operand types are known. Comparisons produce a 32-bit Wasm integer containing 0 or 1, so their results can feed `if`, `eqz`, or further integer operations. Signed and unsigned integer comparisons retain distinct `slt`/`ult`-style operations.
- Integer division and remainder use width- and signedness-specific operations: signed division is named `wasm_i32_div_s_trap_zero_or_overflow` (or the i64 form); unsigned division and signed/unsigned remainder are named `wasm_i32_*_trap_zero` (or the i64 form). Each adds a conditional trap edge in `LiftedBlock::trap_edges` while preserving the normal continuation. Its typed i32 `condition` is exact: division by zero for unsigned division and either zero divisor or signed-minimum divided by `-1` for signed division; all remainders trap only on a zero divisor. The trap edge's `operation` retains the named Wasm operation, and the pseudocode formatter renders it as a named call.
- `unreachable` terminates its block, emits an explicit `wasm_unreachable()` intrinsic, and adds an unconditional trap edge without a normal successor.
- Core numeric conversions and reinterpret operations in opcodes `0xa7..0xbf`. Each conversion retains exact input/output types and signedness in a named IR operator. Each float-to-integer truncation adds a conditional trap edge whose typed i32 `condition` is the named, exact Wasm predicate: the input is NaN, or truncation toward zero would produce an integer outside the destination's signed or unsigned range.
- Saturating float-to-integer conversions `i32.trunc_sat_{f32,f64}_{s,u}` and `i64.trunc_sat_{f32,f64}_{s,u}` in `0xfc` subopcodes `0..7`. The loader validates each exact float input and integer result type; typed lifting emits named unary semantics and adds no trap edge, since NaN maps to zero and out-of-range inputs clamp to the destination bound.
- Sign-extension operations `i32.extend8_s`, `i32.extend16_s`, `i64.extend8_s`, `i64.extend16_s`, and `i64.extend32_s` in opcodes `0xc0..0xc4`. Loader validation checks the i32/i64 stack type, and typed lifting emits `sext8`, `sext16`, or `sext32` unary operations while preserving the Wasm result width.
- Scalar `i32.load`, `i64.load`, `f32.load`, `f64.load`, sign/zero-extending narrow integer loads, and the matching scalar stores in opcodes `0x28..0x3e`. These require loader metadata proving exactly one module memory, check the natural alignment exponent and Wasm32 offset, and lower the effective address with a 32-bit addition into common memory SSA. Each operation also carries a may-trap edge whose i32 condition is a named `wasm_memory_access_out_of_bounds_length_N(effective_address)` predicate, where `N` is the access width in bytes; the predicate accounts for the whole access, with runtime memory size left opaque.
- `memory.size` and `memory.grow` with the MVP memory index zero and exactly one validated module memory. They retain typed i32 results as `wasm_memory_size_pages` and `wasm_memory_grow_pages` intrinsics; growth consumes an i32 delta, has an unknown memory effect, and models runtime failure as the Wasm `-1` result rather than a trap edge.
- Bulk-memory subopcodes `0xfc 8..11`: `memory.init`, `data.drop`, `memory.copy`, and `memory.fill`. The loader validates data indices against a required DataCount section, memory indices against exactly one memory at index zero, and the three i32 stack operands for memory-writing operations. The lifter keeps these as named intrinsics (`wasm_memory_init_data_N`, `wasm_data_drop_segment_N`, `wasm_memory_copy`, and `wasm_memory_fill`); `memory.init`/`memory.copy` have unknown memory effects and `memory.fill` has a write effect. `memory.copy` retains its overlap-safe Wasm operation identity.

The CFG builder accepts at most 100,000 instructions, 16,384 blocks, 128 nested labels, and 128 operand-stack values. At every reachable join, stack height and each slot's type must match exactly; values are carried with stack pseudo-registers and explicit phis. For a block or `if`, its normal end and branches to that label must carry every declared result value in order. The implicit function label uses the function result vector and targets the final `end`; this supports `br`, `br_if`, and `br_table` function exits with the same edge projection and return lowering as ordinary fallthrough. Loop labels use their declared parameter types for branches back to the loop header. Indexed block signatures may declare up to 128 numeric parameters and results. On a branch edge, values below the label height are retained and the label operands are mapped from the top of the source stack; edge-specific projections feed the target's stack phis, so temporaries can now be discarded at joins. If one source block has multiple differently projected edges to the same target, lifting still fails closed because the common IR identifies phi inputs by predecessor block. Incompatible shapes are rejected. The decoder and loader accept up to twelve explicit `br_table` cases, subject to the 15-byte encoded-instruction limit; the lifter applies the same bound.

## Explicit unsupported cases

The loader type-checks complete MVP function bodies and the supported bulk-memory subset against module signatures, locals, globals, calls, data/memory indices, and structured labels before mapping them. Its `WasmMetadata` retains function-indexed expanded local types alongside the existing type-index/signature metadata; CLI and desktop adapters pass this metadata into the lifter. Local lifting supports up to 256 combined parameters and locals, and the operand stack remains capped at 128. Function signatures support up to 128 numeric results. Direct calls support up to 128 numeric parameters and indirect calls up to 127 (the table index also occupies an operand-stack slot); both push each declared result as a distinct typed stack value. Multi-value returns are retained as a `wasm_return_values(...)` intrinsic immediately before the common `return;` terminator. Direct call targets render as `wasm_call_function_N`; call effects are conservatively unknown. `call_indirect` fails closed when type/table immediates or types are unavailable, there is not exactly one table, or the signature shape/type is unsupported; dynamic indices remain runtime operations and carry a may-trap edge. Global accesses require module metadata and fail closed for missing or unsupported types and immutable writes. Structured block entry records the stack prefix beneath its parameters; normal block ends discard arm temporaries and retain only the declared result suffix. Loop labels accept parameter types, while block and if labels accept result types. Branch edges now project label operands onto the target stack and allow intervening temporaries to be discarded. When multiple edges from one source block to the same target need different projections, lifting fails closed because the common IR phi form keys inputs by predecessor block rather than edge. Function references are represented as typed 32-bit `funcref` pointer values: `ref.null funcref` is a null constant, `ref.func` is a named function-reference expression, and `ref.is_null` is a typed i32 predicate. `ref.func` indices must be valid and declared outside function bodies through a function export or supported element segment, following the [WebAssembly Core Specification](https://www.w3.org/TR/wasm-core/#valid-instr-ref-func). Funcref values can flow through typed parameters/results, locals, stack slots, branches, and joins when their types match. Tables, table element initialization and mutation, `call_indirect` reference resolution, externref, host-provided reference identity, and runtime garbage collection are not modeled; unsupported reference operators fail closed. Scalar and bulk-memory operations and memory size/grow require exactly one module memory; multiple memories and exception edges remain unmodeled. Scalar loads and stores carry named may-trap predicates for full-access out-of-bounds checks, but those predicates remain opaque because runtime memory size is unavailable. `memory.init`, `memory.copy`, and `memory.fill` carry typed may-trap predicates for destination/source ranges; `memory.init` also checks its static data segment extent and whether the segment was dropped when the requested length is nonzero. Runtime memory size and data-segment lifecycle remain opaque state. `data.drop` itself has no trap edge. These operations require a DataCount section whose declared count covers each referenced data index, and data initialization state remains represented by the segment-specific intrinsic name. Branches to the implicit function label require exact function signature metadata; malformed control nesting, stack underflow/type mismatch, and incompatible joins fail closed. Integer division/remainder edges carry exact typed zero-divisor predicates and, for signed division, the signed-minimum divided by minus-one overflow predicate. Float-to-integer edges carry named semantic predicates for NaN or a truncated result outside the destination range. Other trap behaviors remain unmodeled.

No type is inferred for an unknown stack value. Unmodeled opcodes and unavailable immediates return `ErrorCode::unsupported`.

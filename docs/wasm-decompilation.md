# WebAssembly function lifting

`lift_wasm_function` is a bounded, fail-closed scalar stack lifter. It consumes a recovered function snapshot, uses each instruction's function-relative address, and constructs typed common-IR expressions from stack constants and scalar numeric operators. It splits the flat function stream into blocks at structured-control operators, branch targets, and fallthroughs. Operand stacks are propagated across reachable CFG edges; matching stack shapes at joins become explicit `wasm_stack` phi values, including loop backedges. A function with a supported return can be represented as a common-IR `Return`.

## Supported instructions

- `nop`, `end`, `return`, `drop`
- `block` and `loop` with an empty, shorthand single-value type, or indexed numeric parameter/result signature; indexed signatures may carry up to 128 numeric parameters and results
- `if`/`else` with an empty, shorthand single-value type, or indexed numeric parameter/result signature; parameters are consumed from the condition's surrounding stack then made available in both arms, and result values join at the end; non-void results require an `else` arm
- `br` and `br_if` when their lexical label depths resolve to a block/loop/if label or the implicit function label, and the complete target stack shape is preserved; a branch to the function label rejoins at the final `end` and returns the declared results
- `br_table` with up to twelve explicit cases, when every case and default depth resolves to an explicit block/loop/if label or the implicit function label and preserves the target stack shape; this becomes a common-IR switch dispatch. Larger tables are rejected by the decoded instruction-size budget
- `select` on same-typed values, emitted as a typed conditional expression
- typed `select` (`0x1c`) for exactly one declared numeric, `funcref`, or `externref` result type; both alternatives are checked against that exact type and emitted as a typed conditional expression
- SIMD bitwise operators `v128.not`, `v128.and`, `v128.andnot`, `v128.or`, `v128.xor`, and `v128.bitselect` (`0xfd 0x4d..0x52`). They consume/produce opaque 128-bit vector values with Wasm stack order preserved. `andnot` is represented as `a & ~b`; `bitselect` is represented as `(a & mask) | (b & ~mask)`, where the mask is the third stack operand. These are typed bit-vector expressions and do not claim lane arithmetic semantics.
- SIMD scalar splats `i8x16.splat`, `i16x8.splat`, `i32x4.splat`, `i64x2.splat`, `f32x4.splat`, and `f64x2.splat` (`0xfd 0x0f..0x14`). Each consumes exactly one scalar of the corresponding Wasm type (`i32` for i8/i16/i32 lanes, `i64` for i64 lanes, and matching `f32`/`f64`) and produces one opaque `v128`. The typed unary operation retains the exact splat kind, including integer lane-width truncation and floating bit pattern replication; it does not evaluate vector lanes.
- Integer SIMD unary operations `i8x16.abs/neg/popcnt/all_true/bitmask`, `i16x8.abs/neg/all_true/bitmask`, `i32x4.abs/neg/all_true/bitmask`, and `i64x2.abs/neg/all_true/bitmask` retain their exact decoded operation in typed unary IR. Each consumes one `v128`; lane transformations produce `v128`, while `all_true` and `bitmask` produce `i32`. The expressions preserve the lane operation without evaluating lane results; missing or unsupported subopcodes remain fail-closed.
- Byte-lane `i8x16.shuffle` and `i8x16.swizzle` preserve all sixteen validated shuffle selectors and the runtime zeroing behavior for swizzle indices outside `0..15`; see the [shuffle/swizzle lifting notes](../libs/decompiler/docs/wasm-simd-shuffle-swizzle.md).
- Finalized Relaxed SIMD subopcodes `0x100..0x113` validate their v128 operands and preserve exact opcode names and operand order as typed opaque intrinsics. They cover relaxed swizzle, relaxed truncation, fused multiply-add, lane select, min/max, Q15 multiply, and dot products. No implementation-dependent result choice is inferred or executed.
- `local.get`, `local.set`, and `local.tee` for numeric MVP locals when the snapshot includes the function signature and expanded declared-local types; parameters initialize from `argN`, declared locals initialize to zero, and local values use dedicated typed pseudo-registers
- direct `call` when the target function index and signature are present in module metadata; arguments and up to 128 numeric results are type-checked, and effectful named intrinsics produce typed stack pseudo-registers for each result
- `global.get` and mutable `global.set` for numeric globals with exact combined imported/defined index, type, and mutability metadata; opaque effectful named intrinsics preserve global ordering
- `call_indirect` when the single table index and exact type index are valid and the numeric signature has up to 127 parameters and 128 results. The runtime i32 table index is preserved, and the call is marked may-trap for a bounds or type mismatch. If that index is a constant into a complete, non-exported defined table and its initial function has the exact requested type index, the intrinsic name includes the function index as a static target hint. The operation retains its may-trap edge because runtime table changes are not modeled.
- `i32.const`, `i64.const`, `f32.const`, `f64.const`
- Numeric comparisons and scalar operators in opcodes `0x45..0xa6` when the exact operand types are known. Comparisons produce a 32-bit Wasm integer containing 0 or 1, so their results can feed `if`, `eqz`, or further integer operations. Signed and unsigned integer comparisons retain distinct `slt`/`ult`-style operations.
- Integer division and remainder use width- and signedness-specific operations: signed division is named `wasm_i32_div_s_trap_zero_or_overflow` (or the i64 form); unsigned division and signed/unsigned remainder are named `wasm_i32_*_trap_zero` (or the i64 form). Each adds a conditional trap edge in `LiftedBlock::trap_edges` while preserving the normal continuation. Its typed i32 `condition` is exact: division by zero for unsigned division and either zero divisor or signed-minimum divided by `-1` for signed division; all remainders trap only on a zero divisor. The trap edge's `operation` retains the named Wasm operation, and the pseudocode formatter renders it as a named call.
- `unreachable` terminates its block, emits an explicit `wasm_unreachable()` intrinsic, and adds an unconditional trap edge without a normal successor.
- Core numeric conversions and reinterpret operations in opcodes `0xa7..0xbf`. Each conversion retains exact input/output types and signedness in a named IR operator. Each float-to-integer truncation adds a conditional trap edge whose typed i32 `condition` is the named, exact Wasm predicate: the input is NaN, or truncation toward zero would produce an integer outside the destination's signed or unsigned range.
- Saturating float-to-integer conversions `i32.trunc_sat_{f32,f64}_{s,u}` and `i64.trunc_sat_{f32,f64}_{s,u}` in `0xfc` subopcodes `0..7`. The loader validates each exact float input and integer result type; typed lifting emits named unary semantics and adds no trap edge, since NaN maps to zero and out-of-range inputs clamp to the destination bound.
- Sign-extension operations `i32.extend8_s`, `i32.extend16_s`, `i64.extend8_s`, `i64.extend16_s`, and `i64.extend32_s` in opcodes `0xc0..0xc4`. Loader validation checks the i32/i64 stack type, and typed lifting emits `sext8`, `sext16`, or `sext32` unary operations while preserving the Wasm result width.
- Scalar `i32.load`, `i64.load`, `f32.load`, `f64.load`, sign/zero-extending narrow integer loads, and the matching scalar stores in opcodes `0x28..0x3e`. These require loader metadata proving exactly one module memory, check the natural alignment exponent and Wasm32 offset, and lower the effective address with a 32-bit addition into common memory SSA. Each operation also carries a may-trap edge whose i32 condition is a named `wasm_memory_access_out_of_bounds_length_N(zext(address) + offset)` predicate, where `N` is the access width in bytes. The trap predicate performs the base-plus-offset calculation in 64 bits before checking the whole access, so an effective address above the Wasm32 range cannot wrap back into an in-bounds address; runtime memory size remains opaque.
- SIMD memory subopcodes `0..11` and `92..93` (`v128.load`, the signed/unsigned 8x8/16x4/32x2 widening loads, scalar splat loads, `v128.store`, and `v128.load32_zero`/`v128.load64_zero`) under opcode `0xfd`. They require metadata proving exactly one memory, two valid memarg immediates, a natural alignment exponent no greater than the actual access width, and a Wasm32 offset. The effective i32 address is lowered into common memory SSA. Loads/stores preserve opaque 128-bit vector types; widening, splat, and zero loads retain a named typed unary operation over the exact 64-bit vector or scalar memory value. Each carries a may-trap edge with the same widened base-plus-offset calculation and actual byte width. Other non-memory SIMD operations remain fail closed.
- `v128.not` (`0xfd 77`) consumes and produces the opaque 128-bit vector type and lowers to the named unary `wasm_v128_not` operation. It supports bitwise complement of vector values already available on the operand stack, including supported SIMD loads and previous `v128.not` results. It does not expose lane values or infer integer/float lane semantics.
- Integer SIMD lane shifts `i8x16`, `i16x8`, `i32x4`, and `i64x2` `shl`, `shr_s`, and `shr_u` under `0xfd` are validated and lifted with exact vector/i32 stack typing. The shift count remains the runtime i32 operand and the lane operation is retained by a named intrinsic.
- Integer SIMD narrowing (`i8x16.narrow_i16x8_{s,u}`, `i16x8.narrow_i32x4_{s,u}`) consumes two opaque vectors and preserves source-vector order in a typed binary expression. Signed and unsigned low/high widening (`i16x8.extend_{low,high}_i8x16_{s,u}`, `i32x4.extend_{low,high}_i16x8_{s,u}`, `i64x2.extend_{low,high}_i32x4_{s,u}`) and pairwise extension-add (`i16x8.extadd_pairwise_i8x16_{s,u}`, `i32x4.extadd_pairwise_i16x8_{s,u}`) consume one vector and produce one vector through exact mnemonic unary expressions. Their opcodes are explicitly recognized in the lifter; other SIMD arithmetic still fails closed.
- SIMD comparisons at `0xfd 0x23..0x4c` and `0xfd 0xd6..0xdb` consume two opaque `v128` values and produce an opaque `v128` lane mask. Their exact decoder mnemonics are preserved in typed binary expressions, including signed/unsigned and lane-width distinctions. The lifter does not evaluate lane comparisons or convert masks into scalar booleans.
- SIMD lane extract and replace subopcodes `21..34` under `0xfd` preserve the validated lane index in named typed operations. Signed and unsigned i8/i16 extraction, i32/i64 extraction, and f32/f64 extraction produce the appropriate scalar stack type; replacement consumes a 128-bit vector and the required scalar type and produces a new vector. Lane bounds are checked against the lane count. Lane-indexed memory operations are documented separately. Other SIMD families remain unsupported unless listed here.
- `memory.size` and `memory.grow` with the MVP memory index zero and exactly one validated module memory. They retain typed i32 results as `wasm_memory_size_pages` and `wasm_memory_grow_pages` intrinsics; growth consumes an i32 delta, has an unknown memory effect, and models runtime failure as the Wasm `-1` result rather than a trap edge.
- Bulk-memory subopcodes `0xfc 8..11`: `memory.init`, `data.drop`, `memory.copy`, and `memory.fill`. The loader validates data indices against a required DataCount section, memory indices against exactly one memory at index zero, and the three i32 stack operands for memory-writing operations. The lifter keeps these as named intrinsics (`wasm_memory_init_data_N`, `wasm_data_drop_segment_N`, `wasm_memory_copy`, and `wasm_memory_fill`); `memory.init`/`memory.copy` have unknown memory effects and `memory.fill` has a write effect. `memory.copy` retains its overlap-safe Wasm operation identity.
- Table-operation subopcodes `0xfc 12..17`: `table.init`, `elem.drop`, `table.copy`, `table.grow`, `table.size`, and `table.fill`. Lifting requires loader metadata proving exactly one funcref table at index zero and valid element-segment indices. Operations remain named intrinsics so stack values and ordering are explicit. `table.size` is a read; table mutation/drop/grow uses an unknown state effect. `table.grow` returns the old size or Wasm's `-1` failure value. `table.init` adds a may-trap condition for destination bounds, element-source bounds, and a dropped element segment with nonzero length; `table.copy` checks source and destination bounds while preserving overlap-safe copy identity; `table.fill` checks destination bounds. Runtime table size and segment lifecycle are opaque predicates.

The CFG builder accepts at most 100,000 instructions, 16,384 blocks, 128 nested labels, and 128 operand-stack values. At every reachable join, stack height and each slot's type must match exactly; values are carried with stack pseudo-registers and explicit phis. For a block or `if`, its normal end and branches to that label must carry every declared result value in order. The implicit function label uses the function result vector and targets the final `end`; this supports `br`, `br_if`, and `br_table` function exits with the same edge projection and return lowering as ordinary fallthrough. Loop labels use their declared parameter types for branches back to the loop header. Indexed block signatures may declare up to 128 numeric parameters and results. On a branch edge, values below the label height are retained and the label operands are mapped from the top of the source stack; edge-specific projections feed the target's stack phis, so temporaries can now be discarded at joins. If one source block has multiple differently projected edges to the same target, the lifter inserts bounded edge-bridge blocks so the common IR's predecessor-keyed phi representation preserves each projection. Incompatible shapes are rejected. The decoder and loader accept up to twelve explicit `br_table` cases under the encoded-instruction size limit; the lifter applies the same bound.

## Explicit unsupported cases

The loader type-checks complete function bodies and supported bulk-memory and table operations against module signatures, locals, globals, calls, data/element/table/memory indices, and structured labels before mapping them. Its `WasmMetadata` retains function-indexed expanded local types alongside the existing type-index/signature metadata; CLI and desktop adapters pass this metadata into the lifter. Local lifting supports up to 256 combined parameters and locals, and the operand stack remains capped at 128. Function signatures support up to 128 numeric results. Direct calls support up to 128 parameters and indirect calls up to 127 (the table index also occupies an operand-stack slot); both push each declared result as a distinct typed stack value. Multi-value returns are retained as a `wasm_return_values(...)` intrinsic immediately before the common `return;` terminator. Direct call targets render as `wasm_call_function_N`; call effects are conservatively unknown. `call_indirect` fails closed when type/table immediates or types are unavailable, there is not exactly one table, or the signature shape/type is unsupported. Dynamic indices remain runtime operations and carry a may-trap edge with a typed opaque predicate over the runtime i32 table slot and expected type index; the predicate represents an out-of-bounds slot or a null/type-mismatched entry, while runtime table size and contents remain unavailable. A target hint is emitted only for a constant slot in a complete, non-exported defined table whose function type index exactly matches the instruction's type index; imported, exported, incomplete, null, out-of-range, or type-mismatched slots remain indirect. The may-trap edge remains even when a target hint is present because runtime table changes are not modeled; its predicate retains the table slot and exact expected type index. The loader and lifter validate table-operation instructions; the lifter preserves their runtime effects as named intrinsics and models the specified bounds traps, while exact table contents and runtime limits remain opaque. Global accesses require module metadata and fail closed for missing or unsupported types and immutable writes. Structured block entry records the stack prefix beneath its parameters; normal block ends discard arm temporaries and retain only the declared result suffix. Loop labels accept parameter types, while block and if labels accept result types. Branch edges now project label operands onto the target stack and allow intervening temporaries to be discarded. When edges from one source block to the same target need different stack projections, lifting inserts a synthetic edge bridge for each additional projection. The originating branch or switch case routes through that bridge; the bridge copies the selected source stack slots, then reaches the original target as a distinct predecessor. This preserves the common IR predecessor-keyed phi representation without conflating edge-specific stack values. Bridge blocks count toward the existing CFG block limit. Unsupported instruction semantics and incompatible target stack shapes still fail closed. `funcref` values use the common IR's 32-bit pointer representation, while `externref` values use that same opaque reference representation; module validation preserves their distinct Wasm types. `ref.null funcref` and `ref.null externref` lift to null values, `ref.func` is rendered as `wasm_function_ref(index)`, and `ref.is_null` produces a typed i32 predicate for either reference type. Both reference types are accepted in function signatures, locals, globals, and typed select. Exact nullness facts propagate through parameters and locals after assignment or branch refinement, copies, globals, and reachable control-flow joins only when all incoming facts agree; mutable global facts are invalidated by calls. The bounded stack-fact transfer also preserves `ref.null`/`ref.func` nullness through `select` when its condition is constant or both alternatives have the same fact, including when the result is assigned to and later read from a local. Facts are discarded when an unmodeled stack operation makes the abstract stack uncertain. A direct `ref.is_null` test of a local or global also refines that reference on the true and false successors of `br_if` and `if`; a following `i32.eqz` reverses which edge means null. Refinements merge with other incoming paths and disappear when facts disagree. Unrefined parameters remain unknown, and this refinement does not follow aliases or arbitrary boolean expressions. Mixed joins and stack values obscured by other operations remain runtime predicates. `ref.func` indices must be valid and declared outside function bodies through a function export or supported element segment, following the [WebAssembly Core Specification](https://www.w3.org/TR/wasm-core/#valid-instr-ref-func). Table contents remain metadata-only: only constant-slot call_indirect hints are resolved; table mutation is retained as named opaque effects, and host table state is not modeled. Externref identity, `ref.eq`, and runtime garbage collection remain unsupported; unsupported reference operators fail closed. Scalar and bulk-memory operations and memory size/grow require exactly one module memory; multiple memories and exception edges remain unmodeled. Scalar loads and stores carry named may-trap predicates for full-access out-of-bounds checks, but those predicates remain opaque because runtime memory size is unavailable. `memory.init`, `memory.copy`, and `memory.fill` carry typed may-trap predicates for destination/source ranges; `memory.init` also checks its static data segment extent and whether the segment was dropped when the requested length is nonzero. Runtime memory size and data-segment lifecycle remain opaque state. `data.drop` itself has no trap edge. These operations require a DataCount section whose declared count covers each referenced data index, and data initialization state remains represented by the segment-specific intrinsic name. Branches to the implicit function label require exact function signature metadata; malformed control nesting, stack underflow/type mismatch, and incompatible joins fail closed. Integer division/remainder edges carry exact typed zero-divisor predicates and, for signed division, the signed-minimum divided by minus-one overflow predicate. Float-to-integer edges carry named semantic predicates for NaN or a truncated result outside the destination range. Other trap behaviors remain unmodeled.

Table operations are now lifted as named intrinsic effects. Exact table contents and runtime limits remain opaque, and their named bounds predicates are not evaluated without an execution environment.

No type is inferred for an unknown stack value. Unmodeled opcodes and unavailable immediates return `ErrorCode::unsupported`.

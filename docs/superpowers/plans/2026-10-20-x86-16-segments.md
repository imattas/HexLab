# x86-16 Segmented Analysis Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans inline, one task at a time, with one fresh final review for this whole subproject. User standing authorization removes approval checkpoints.

**Goal:** Deliver original scalar16 decoding and persistent segmented raw real/protected profiles through shared C++ services, CLI and wxWidgets.

**Architecture:** Keep logical domains in AddressSpaceId/offset, translate through explicit checked real/protected rules and canonical file backing, and decode with the address's execution context. Extend existing libraries and workflows rather than introducing unused placeholder modules. Preserve flat32/64 behavior and package layout.

**Tech Stack:** C++20, existing exported CMake DLLs, wxWidgets3.2.12, SQLite, original parser/recovery, test-only pinned QEMU/Bochs/NASM plus authored16 probes.

**Spec:** docs/superpowers/specs/2026-10-20-x86-16-segments-design.md

## Global constraints and execution rulings

- Existing x64/32 recipe v1 bytes, enum values and project history stay compatible. New segmented profiles are versioned; derived data can recompute without migrating authoritative user schema1.
- Real/protected translation is explicit. No guessed selectors, fabricated unique aliases, foreign production decoder, GUI I/O/decode/SQL, or test-only emulator in production dependencies.
- All address lookup/sorting uses space plus offset. Code default size, stack address/value size and linear/physical/file positions stay distinct.
- Profile limits include bounds, descriptor counts, byte order, valid enums, initialized backing, A20 policy and domain context. Unknown/unsupported machine transitions stay typed partial/unresolved.
- Full consumer rebuild after public value changes; never edit shared source/header/CMake during dependent builds. No concurrent Debug/Release builds in one tree.
- Existing unborn feat/foundation workspace has no Git base or identity. Preserve it and installed ProjectAnalysisDebug/X86ModeDebug baselines; no commits, merge/cleanup menu or approval questions. New delivery prefix is SegmentedDebug.
- The full original IDA-class goal and all later stages remain active; this plan's completion does not complete the goal.

## Review focus

1. Same numeric offset in two logical domains, selector aliases and ambiguous reverse lookup.
2. Segment limits versus A20 wrapping, empty spans and protected expand-down/D-B flags.
3. Default16 encoding versus 32-bit EIP/stack attributes, far pointers and return continuations.
4. Wrong per-domain context/profile in checksum-recomputed caches and late worker results.
5. Persistent decisions and original-byte export across profile edits, source-missing reopen and mixed-mode tabs.

## File responsibilities

- core/include/hexlab/core/x86_segments.hpp and core/src/x86_segments.cpp: trivial coordinates, checked descriptor parsing and real/protected span translation.
- image image.hpp/image.cpp and focused domain/segment mapping sources: space/context indexes, immutable aliases, per-space validation and translation.
- processors architecture.hpp/decoder/instruction values and shared x64_* sources: stack attribute, default16 rules, far operands/effects/format and explicit unsupported forms.
- loaders x86_raw_profile.hpp, segmented_raw.cpp and bounded profile codec; raw/recipe: validated persistent profile and derived mappings, no production file reinterpretation.
- analysis recovery/blocks/references/cache and workspace decisions/listing/search/adoption: domain-aware contexts, identity and current-source barriers.
- CLI parsers/help and desktop mapping/navigation/views: shared profile handling and segment-aware UX with worker parsing.
- tests x86_segments_tests, image_domains_tests, x86_16_decoder_tests, segmented_project_tests, desktop_segment_tests and fixtures/x86_16_oracle: independent literal/integration/execution proof.
- docs/x86-16-coverage.csv and segmented-analysis-validation.md: exact tested subsets and delivery limits.

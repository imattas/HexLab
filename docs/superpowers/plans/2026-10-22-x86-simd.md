# Typed x86 SIMD Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add original typed decode and display support for the initial SSE2 integer and scalar floating-point instruction slice.

**Architecture:** Reuse the existing x86 parser state and address decoder, adding a dedicated SIMD opcode-family source. Append stable register-bank and opcode values, represent XMM and memory operands through existing operand variants, and integrate exact formatting and CLI regressions.

**Tech Stack:** C++20, existing x86 decoder, typed `Instruction`/`Operand` model, CMake, CTest.

**Spec:** [2026-10-22-x86-simd-design.md](../specs/2026-10-22-x86-simd-design.md)

## Global Constraints

- Append enum values only; do not renumber persisted architecture, mode, register-bank, or opcode values.
- Preserve x86 mode-specific addressing and REX register-extension rules.
- Keep invalid, unsupported, and truncated outcomes distinct.
- Reuse the existing x86 prefix, ModRM, SIB, and instruction-finalization paths.
- This slice does not claim lane-exact scalar move behavior, SIMD decompilation, or broader ISA coverage.

## Review Focus

- Mandatory-prefix conflicts and missing mandatory prefixes must not decode as another instruction.
- Truncation at opcode, ModRM, SIB, and displacement boundaries must not read past input or return a partial instruction.
- REX.R/B extension is legal only in 64-bit mode; test both XMM8/XMM15 and legacy-mode rejection.
- Register-register and load/store forms must agree on operand direction and read/write facts.
- Scalar memory widths must stay 32/64-bit while packed memory widths stay 128-bit.

## File Map

- Create `libs/processors/src/x64_simd.cpp`: supported opcode decoding and local SIMD ModRM adapter.
- Modify `libs/processors/src/x64_internal.hpp`: private decoder declaration.
- Modify `libs/processors/src/x64_decode.cpp`: route supported `0F` forms before generic F2/F3 rejection.
- Modify `libs/processors/include/hexlab/processors/instruction.hpp`: append XMM register bank and opcodes.
- Modify `libs/processors/src/format.cpp`: XMM register names and SIMD mnemonics.
- Modify `libs/processors/CMakeLists.txt`: include new decoder source.
- Create `tests/x64_simd_tests.cpp`: direct typed decode, formatting, effects, invalid, and truncation tests.
- Modify `tests/CMakeLists.txt`: register the decoder target and CLI test.
- Modify `tests/fixture_generator.cpp` or create a focused fixture generator: raw representative SIMD byte stream.
- Modify `tests/x64_simd_cli_tests.cmake`: verify raw CLI assembly output.
- Create `docs/x64-simd-coverage.md`: coverage and explicit unsupported boundaries.

The parent integration owner currently holds the public processor header, formatter, processor CMake, test CMake, CLI, and capability-ledger files for PowerPC integration. Do not touch those files until the parent releases them. The SIMD source/test/docs groundwork may proceed independently; final integration must append the shared API and register build/test targets after release.

## Tasks

### Task 1: Decoder fixtures and expected typed behavior

**Files:** Create `tests/x64_simd_tests.cpp`.

**Interfaces:** Consumes public `decode_instruction` and `format_instruction`; the test references the append-only XMM/opcode additions named in the spec once the shared API is available.

- [ ] Add table-driven byte fixtures for all listed packed and scalar opcodes in register-register, load, or store forms as applicable.
- [ ] Assert opcode, instruction length, XMM indexes/128-bit widths, memory widths/address registers, operand access, register reads/writes, memory facts, and formatted assembly.
- [ ] Add 32-bit legacy XMM register tests and long-mode REX.R/B tests for XMM8–XMM15.
- [ ] Add negative tests for unsupported families, malformed mandatory-prefix combinations, and legacy-mode REX-like bytes.
- [ ] Add truncation tests for prefix/opcode/ModRM/SIB/displacement boundaries.

### Task 2: Original SIMD decode family

**Files:** Create `libs/processors/src/x64_simd.cpp`; modify `libs/processors/src/x64_internal.hpp` and `libs/processors/src/x64_decode.cpp` after the parent releases x86 parser integration.

**Interfaces:** `bool simd(State &, std::uint8_t opcode, bool extended)` consumes the active `State` after prefixes and opcode bytes are parsed. It returns false for unrelated opcode bytes, sets typed instruction operands for supported forms, and uses `invalid`, `unsupported`, and `State::take` to preserve result distinctions.

- [ ] Add a private ModRM adapter that preserves existing memory addressing while mapping ModRM XMM operands into the XMM bank.
- [ ] Decode `movdqa`, `movdqu`, `paddd/q`, `psubd/q`, `pand`, `por`, and `pxor` with exact mandatory prefixes and operand access.
- [ ] Decode `movss/sd` load/store/register forms with scalar-width memory operands.
- [ ] Decode `add/sub/mul/div` SS/SD forms with read/write destination and read source.
- [ ] Route SIMD forms ahead of generic F2/F3 rejection and retain generic fallback behavior for unrelated forms.

### Task 3: Stable public API, names, and build integration

**Files:** Modify `instruction.hpp`, `format.cpp`, processor `CMakeLists.txt`, and `tests/CMakeLists.txt` after parent release.

**Interfaces:** Append one `RegisterBank::xmm`; append the 19 `Opcode` values in spec order. Add XMM name formatting (`xmm0`–`xmm15`) and exact lowercase mnemonic formatting. Compile `x64_simd.cpp` into the processor library and register `hexlab_x64_simd_tests`.

- [ ] Append register-bank and opcode values without moving existing enum values.
- [ ] Format valid XMM operands and every SIMD opcode; keep unknown values guarded.
- [ ] Add the decoder source and focused test executable to their existing CMake targets.

### Task 4: CLI raw workflow and coverage docs

**Interfaces:** The CLI uses existing `--format raw --arch x86-64 --base` selection; no new product option is introduced. The fixture contains representative packed arithmetic, a packed load/store, and scalar floating arithmetic/move forms.

- [ ] Verify CLI output includes expected packed/scalar mnemonics and XMM operands from the fixture.

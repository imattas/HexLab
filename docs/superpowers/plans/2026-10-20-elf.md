# ELF32/ELF64 implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement inline task by task. One fresh independent reviewer at completion; no implementer delegation.

**Goal:** Native original ELF32/ELF64 executable/shared-object/object inspection, analysis and persistent CLI/wx workflows in the shared suite.

**Architecture:** Bounded ByteStorage parsing, PT_LOAD executable mappings and section-domain REL mappings; typed ELF metadata feeds shared analysis and worker/project services. Preserve PE/raw compatibility and source bytes.

**Tech stack:** C++20, CMake, MSVC, existing DLL engines, SQLite and wxWidgets; independent test-only ELF inspection tools.

**Spec:** docs/superpowers/specs/2026-10-20-elf-design.md

## Global constraints

- Original C++20 implementation; no new production dependency or foreign decoder/parser.
- Preserve old enum ordinals, flat/segmented recipe bytes and authoritative project history; derived caches may recompute.
- Full64-bit typed ELF metadata; no truncation into PE RVA/ordinal structures.
- Bounded/cancellable worker parsing; no GUI I/O/SQL/decode or execution of user binaries.
- Program headers<=65536; section headers<=1048576; metadata bytes<=64MiB.
- Preserve unborn feat/foundation, existing source and accepted installation baselines; no commits/cleanup/approval prompts.
- Full consumer rebuild on public layout changes; no mutations during dependent builds/tests; Debug/Release sequential in one tree.
- New installation ElfDebug; full goal remains active after this plan completes.

## Review focus

1. Sectionless shared objects and executable/section disagreement must use load mappings and honest bounded metadata (tasks2/4).
2. Identical numeric REL symbol offsets in different sections must preserve domain/annotation identity (tasks2/3/6).
3. Extended counts/large strides/unterminated strings must be checked before reads/allocation (tasks1/3/4).
4. Patching ELF header/symbol/relocation bytes must invalidate metadata/facts without mutating originals/history (task5).
5. Compatible overlap/BSS or unknown machine context must never fabricate canonical backing or x86 flow (tasks2/6).

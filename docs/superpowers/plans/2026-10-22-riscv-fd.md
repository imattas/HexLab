# RISC-V F/D Scalar Floating-Point Implementation Plan

> **For agentic workers:** Follow this plan task by task; each task includes a test-first cycle.

**Goal:** Decode and lift the bounded scalar F/D instruction families in the accepted design spec.

**Architecture:** Append RISC-V FPR/status register-bank and opcode values, decode F/D words into typed existing operands plus rounding/exception facts, adapt and format them through generic dispatch, and teach only the RISC-V decompiler path to emit floating-typed assignments or named intrinsics. Existing integer processor/decompiler behavior remains unchanged.

**Tech Stack:** C++20, CMake/CTest, MSVC Visual Studio generator, existing processor and decompiler libraries.

**Spec:** `docs/superpowers/specs/2026-10-22-riscv-fd-design.md`

## Global Constraints

- Append public enum values to preserve serialized ordinals.
- Keep opcode/register additions specific to RISC-V; do not refactor unrelated architectures.
- Preserve explicit distinctions among decoded, invalid, unsupported, and truncated instructions.
- Do not edit `docs/capabilities.csv` or top-level CMake files.
- Do not claim NaN-boxing, IEEE evaluation, runtime rounding selection, or precise `fflags` values.
- Use `.agent-riscv-fd-vsbuild` for all generated build outputs.

## Review Focus

- Reserved rounding values 5/6 must reject the encoding, while dynamic value 7 is retained: decoder tests.
- FMA format/reserved fields and width-specific conversion selectors must distinguish invalid from unsupported: decoder tests.
- RV64F destination values occupy the physical FPR bank even though S view/value widths are 32 bits: dispatch/lifter tests.
- FP comparisons and conversions target the integer bank, while their inputs use FPR: decoder/lifter tests.
- FP arithmetic writes accrued status and memory forms retain data width separately from XLEN address width: decoder/SSA tests.

## File Map

- `libs/processors/include/hexlab/processors/instruction.hpp`: append FPR/status banks, FP opcodes, and rounding/fflags metadata.
- `libs/processors/include/hexlab/processors/riscv.hpp`: append F/D decoder opcodes and source-level FP facts.
- `libs/processors/src/riscv.cpp`: decode memory, OP-FP, and fused-operation formats with precise validation.
- `libs/processors/src/dispatch.cpp`: preserve FP register, operand, rounding, and accrued-flag facts in generic instructions.
- `libs/processors/src/format.cpp`: format F/D mnemonic names and rounding modes.
- `libs/decompiler/include/hexlab/decompiler/decompiler.hpp`: add floating value type kind.
- `libs/decompiler/src/decompiler.cpp`: lift only supported RISC-V F/D forms and route unrepresented side effects through explicit intrinsics.
- `tests/riscv64_decoder_tests.cpp`: literal, malformed, truncated, and RV32/RV64 F/D decoder cases.
- `tests/processor_modes_tests.cpp`: generic dispatch and assembly formatting cases.
- `tests/decompiler/riscv_lifting_tests.cpp`: typed F/D lifting, effects, and SSA independence.
- `docs/riscv64-coverage.md`, `docs/riscv-decompiler.md`: record implemented family boundary and non-goals.

## Tasks

### Task 1: F/D register and opcode model plus FP memory operations

**Interfaces:** Produce `RegisterBank::riscv_fpr`, `RegisterBank::riscv_fstatus`, appended F/D opcodes, optional `rounding_mode`, and `writes_fflags` facts. S and D use a 64-bit physical FPR operand; `MemoryOperand::data_width` remains 32 or 64 and `address_width` remains XLEN.

- [ ] Add literal FLW/FSW/FLD/FSD tests for operands, banks, widths, and memory direction; verify truncated encodings remain truncated.
- [ ] Run `hexlab_riscv64_decoder_tests` and confirm new valid forms fail because they are currently unsupported.
- [ ] Implement decoder memory cases and adapt decoder tests for reserved `funct3` encodings.
- [ ] Re-run the focused decoder target and test.

### Task 2: Arithmetic, FMA, comparison, conversion, and move/class decode

**Interfaces:** Consume Task 1's appended types. Produce all S/D instruction identities, integer/FPR operand-bank assignments, rounding mode `0..4` or dynamic `7`, and FP status write facts.

- [ ] Add literal known-answer tests for S/D arithmetic, sqrt, four FMA opcodes, comparisons, classification, signed/unsigned integer conversions, S/D conversion, and raw moves.
- [ ] Add malformed tests for reserved rounding `5/6`, unsupported `fmt`, reserved FMA `rs3/fmt` combinations, invalid `rs2` selectors, and RV32-only/RV64-only conversion cases; observe the expected failures first.
- [ ] Implement OP-FP and FMA group decoders. Preserve valid unimplemented encodings as unsupported and reserved encodings as invalid.
- [ ] Verify all literal and malformed cases in `hexlab_riscv64_decoder_tests`.

### Task 3: Generic dispatch and assembly formatting

**Interfaces:** Consume Task 2 source facts. Produce generic RISC-V F/D opcodes, 64-bit physical FPR operands, XLEN-width GPRs, accurate memory direction, and formatting with `.s`/`.d` names and static/dynamic rounding suffixes.

- [ ] Add generic decode tests for bank identity, operand width, fflags effects, and canonical examples such as `fadd.s f3, f1, f2, rne`, `fmadd.d f4, f1, f2, f3, dyn`, and `flw f2, 0x4(x5)`.
- [ ] Verify the generic test fails before dispatch/formatter support.
- [ ] Extend the RISC-V dispatch adapter and formatter, leaving other architecture paths unchanged.
- [ ] Build and run `processor_modes` plus the direct decoder test.

### Task 4: Typed F/D lifting and SSA behavior

**Interfaces:** Consume the generic instruction facts from Task 3. Add `TypeKind::floating` and lift typed S/D loads, stores, arithmetic, FMA, comparisons, and conversions. Operations whose rounding/`fflags` effects cannot fit a pure expression are named intrinsics with typed operands and destination/status outputs.

- [ ] Add lifting assertions for floating type widths, S/D load/store access, FMA arity, comparison boolean-to-GPR results, conversion source/destination banks, and explicit status outputs.
- [ ] Verify each new lifting assertion fails because floating opcodes currently fall through to unknown intrinsics.
- [ ] Add the RISC-V-only lift handling. Keep FP arithmetic, conversion, and FMA out of integer constant folding.
- [ ] Add SSA assertions that FPR and GPR destinations receive independent versions and fflags writes remain explicit.
- [ ] Run `decompiler_riscv_lifting` and processor tests.

### Task 5: Focused documentation and regression verification

- [ ] Update `docs/riscv64-coverage.md` with exact F/D families, supported rounding behavior, and architectural limitations.
- [ ] Update `docs/riscv-decompiler.md` to describe typed values/intrinsics and unsupported IEEE/runtime modeling.
- [ ] Build the focused processor/decompiler targets in the dedicated build directory and run `processors`, `riscv64_decoder`, `processor_modes`, and `decompiler_riscv_lifting`.
- [ ] Inspect the changed-file list and verify neither capability/reference CSVs nor top-level CMake changed.

# Desktop bookmark workflow

The **Bookmarks** metadata page projects the active project's persistent bookmarks. Activate a row to navigate to its location. The row's state column keeps unmapped bookmarks visible as orphaned instead of silently dropping them.

The **Jump to location** command also accepts a project bookmark label, user-defined name, or analyzed function name (case-insensitively) in virtual-address mode. Matching is exact; a checked `name+0x10` or `name-4` displacement can target nearby instructions. Loaded segment names are available through `section:.text+0x20` and `segment:.text+0x20`, bounded by the mapped segment extent. If more than one distinct location matches, HexLab reports the ambiguity and leaves the current selection unchanged. Numeric virtual addresses, qualified virtual addresses, file offsets, and segmented addresses keep their existing formats.

Select a row and use **Rename label...** to update its label or **Remove bookmark** to delete it. Both actions submit the existing `BookmarkCommand` through the active document actor, so the change participates in project history, undo/redo, and normal project saving. The table is refreshed from the immutable project projection after the command completes; switching documents does not redirect a pending edit to another project.

Use **Navigate > Previous Annotation / Bookmark** and **Next Annotation / Bookmark** (Alt+Up and Alt+Down) to walk the active project's saved annotation and bookmark locations. Locations are ordered by address space and offset, with file offsets after virtual addresses; duplicate markers at one location are visited once. The commands stop at either end, and each move uses normal document navigation so the listing, bytes, pseudocode, graph, and Back/Forward history stay synchronized.

The desktop project integration test adds a persisted bookmark through the project actor, checks its wx table projection, opens the actual **Jump to location** command, enters the label, and verifies that the selected address changes. It then adds an annotation at another address and exercises both marker commands, checking that selection and the bytes view move together, before removing the bookmark through the wx controls. It also covers duplicate-address handling and ambiguous-name rejection in the shared resolver. Label edits use the same command path as the existing bookmark toggle action.

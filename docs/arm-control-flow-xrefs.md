# ARM register-derived control-flow references

The reference index can now resolve selected AArch64 `BR`/`BLR` and ARM A32/Thumb `BX`/`BLX` targets when function-level register propagation proves the target. The target must map to an executable image segment. ARM interworking bit 0 is used to select the physical target address; A32 targets are aligned to four bytes and Thumb targets to two.

AArch64 values can come from the existing `MOVZ`/`MOVN`/known-input `MOVK`, `ADR`/`ADRP` plus immediate `ADD`/`SUB`, an unshifted `ORR` register-copy alias, or a validated full-width static pointer load. A32/Thumb values can come from `ADR`, PC-relative or tracked-base `ADD`/`SUB`, register/immediate `MOV`, and a validated full-width static pointer load. Calls invalidate the corresponding propagated register state.

Propagation follows only resolved function CFG edges and uses the shared 100,000-block and 1,000,000-edge bounds. At joins, a register fact survives only when all incoming paths agree. For predicated A32/Thumb data-processing writes to PC, an unknown predicate blocks state propagation but does not block a possible-target xref when the pre-instruction operands and target mode are uniquely proven. Incomplete ownership, unresolved edges, unsupported instruction effects, relocation-covered pointer slots, or a target outside executable mapped bytes leave the indirect reference unresolved. A resolved reference retains the source branch instruction identity and is marked with dataflow provenance; this ARM/AArch64 path does not yet publish a full producer instruction chain.

A32 `LDM` with S=1 is decoded only when it is a load whose register list contains PC: this is the exception-return form. It reads SPSR, invalidates the modeled NZCV facts restored into CPSR, and is represented as an indirect jump (or return for the existing SP-based IA/writeback pattern). The loaded PC does not use ordinary bit-zero interworking: execution state and mode come from restored SPSR T/J/mode bits. Since the current static function analysis does not prove those saved bits, it emits no resolved control target for this form. S=1 stores and loads without PC (user-register transfers) remain unsupported, as do other exception-return encodings.

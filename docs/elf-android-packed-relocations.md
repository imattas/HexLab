# Android APS2 packed ELF relocations

HexLab reads Android's `APS2` packed `REL` and `RELA` dynamic relocation streams when an ELF dynamic table supplies `DT_ANDROID_REL` / `DT_ANDROID_RELSZ` or `DT_ANDROID_RELA` / `DT_ANDROID_RELASZ`. Decoded rows use the shared ELF relocation model, so consumers can associate the decoded type, symbol index, addend, target place, and source provenance with other ELF relocation rows.

The decoder validates the `APS2` signature, bounded source extent, signed LEB128 operands, group flags and counts, cumulative offset/addend arithmetic, symbol indexes, and target mappings. It accepts at most 1,000,000 decoded rows and a packed input no larger than the loader's ELF metadata limit. Each row points back to the encoded group byte span because APS2 fields may be shared by several relocations; `record_stride` therefore describes the group's encoded extent rather than a fixed-width ELF record. A malformed stream fails the ELF load instead of yielding a partial table.

This is dynamic-tag-driven support for ELF32/ELF64 `ET_EXEC` and `ET_DYN` in either byte order. It does not unpack section-only Android relocation data without matching dynamic tags, execute IFUNC resolvers, or implement general Android linker behavior. Unsupported relocation formulas remain metadata and are not applied by the existing runtime overlay. The format and tag values follow Android Bionic's published ELF definitions and relocation iterator: [Bionic `elf.h`](https://android.googlesource.com/platform/bionic/+/main/libc/include/elf.h), [Bionic packed relocation iterator](https://android.googlesource.com/platform/bionic/+/main/linker/linker_reloc_iterators.h).

# Desktop type-library workflow

The Type & Symbols workspace exposes **Type Library...** for HXTL portable libraries. Export writes the current named type definitions, declaration kind and available source provenance, plus virtual-address and file-offset type assignments, to a user-selected `.hxtl` file. HXTL v6 includes the input size and SHA-256 as a dedicated binary identity for file-offset assignments, plus the encoded loader-recipe SHA-256 for source identity. Publication uses a same-directory temporary and the project protected-path list; overwriting an existing destination follows the file dialog's confirmation.

Import reads at most 16 MiB and decodes the HXTL bundle before offering a preview. The preview reports new, identical and conflicting definitions and the assignment totals. It uses the shared bounded library-import planner to validate the type-reference graph and resolve the assignments that are eligible for this destination before presenting the merge policy. The user chooses **Keep existing rows** or **Replace conflicting rows**. The keep policy omits conflicting definitions and occupied assignment locations; replace updates those rows. Identical definitions and assignments are omitted. New definitions may reference other definitions in the same bundle or existing project types; missing named references stop import with a validation error.

Address assignments are applied only when the complete input and recipe identity matches. File-offset assignments require an exact binary size and SHA-256 match, even when the loader recipe differs. If an HXTL assignment also carries a source-byte witness, the importer hashes that exact destination range in bounded chunks and selects it only when the digest matches. When the original input bytes are unavailable, a witnessed assignment is skipped. The preview reports selected assignments and skipped counts broken down by source identity mismatch, binary identity mismatch, unavailable witness verification, and witness mismatch. A byte-range fingerprint cannot authorize applying an offset to another image. Missing or mismatched identity skips the affected assignments while definitions remain importable; legacy definition-only HXTL files remain importable.

The selected changes are assembled into one `ImportPortableTypes` project command, checked against the current project snapshot, and submitted through the standard project command path. The workspace transaction therefore applies the import atomically and records it in ordinary project undo/history. The desktop uses the same bounded symbolic-reference walker as CLI import, with a 262,144-node limit and four-million-edge limit. It checks member, parameter, method, virtual-base pointer, static-data, result, and element types. Assignment names are checked whenever the selected policy applies those rows. Assignment and definition limits are enforced by the HXTL codec, and the encoded file is capped at 16 MiB.

Unsupported cases: export stops if an assignment refers to a missing type row. Assignment import does not remap offsets using symbols, sections, or code analysis. The bundle does not export debug variables or arbitrary project metadata.

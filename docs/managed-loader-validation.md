# Managed PE metadata inspection

HexLab can inspect the CLR directory in a PE image through `parse_managed_pe` in `hexlab/loaders/managed.hpp`. It validates the `IMAGE_COR20_HEADER`, maps the metadata RVA through the already validated PE image, and parses the ECMA-335 metadata root and its stream directory. It accepts `#~` and `#-` table streams and computes row counts and row sizes for metadata tables 0 through 44 using heap, table-index, and coded-index width flags.

`parse_cil_method_body` accepts a bounded method-body byte span and returns the IL bytecode plus header fields (`max_stack`, local signature token, initialization flag, and extra-section flag). It handles tiny and fat headers and validates aligned extra-section extents, including exception-clause record sizing. For EH sections, it decodes small and fat clauses and retains clause kind, ranges, catch token or filter offset, raw flags, encoding width, and section/clause provenance. It rejects unsupported clause flags, empty or out-of-body try/handler ranges, malformed catch tokens, invalid filter offsets, and nonzero reserved fields. It also retains optional IL-table section metadata without interpreting its semantics. It does not decode IL opcodes.

`parse_managed_types` reads TypeDef rows from `#~` or `#-`, resolves bounded names and namespaces from `#Strings`, and maps MethodList ranges (including MethodPtr indirection) to MethodDef tokens. `parse_managed_methods` reads stable tokens, RVAs, flags, signature-blob indices, names, and declaring type names. `inspect_managed_methods` composes CLR-header parsing, method enumeration, safe body extent reads, method-body parsing, and CIL decoding from a `LoadedImage`. Project open already reconstructs this `LoadedImage` from durable input, so this catalog is derived on demand rather than saved as duplicate database state. Results distinguish decoded IL, methods with no IL body, unsupported non-IL method code types, and malformed bodies per method.

This is metadata and body loading, not a CLR runtime or full .NET decompiler. The current API does not decode method signatures, local/argument names, generic instantiations, or referenced metadata heaps beyond type and method names; it does not interpret ReadyToRun, mixed-mode native entry points, or runtime-specific metadata beyond ECMA-335 tables 0–44. Every input is size-bounded: 32 streams, one million rows per table, a 64 MiB metadata root, 16 MiB IL per method, and 16 extra sections (32 MiB total body extent). Unknown metadata table bits are reported unsupported instead of guessed. Method RVAs into zero-fill or across segment boundaries are reported malformed rather than read as valid IL.

Validation: `hexlab_managed_loader_tests` exercises metadata stream and table sizing, PE CLR-header integration, TypeDef ownership and MethodDef name/token parsing, invalid ownership-range rejection, end-to-end RVA-to-decoded-instruction output, no-body and malformed methods, tiny and fat CIL bodies, and malformed/truncated inputs.

# MOS 6502 decoder slice

The original C++ decoder is selected with `Architecture::mos6502` and
`ExecutionMode::m6502`. Raw images can use `--format raw --arch 6502 --base`
or the desktop raw mapping dialog. Mapped addresses are byte addressed and
bounded to the 16-bit CPU address space.

The decoder recognizes all 151 documented NMOS opcodes with their official
instruction lengths. It covers the documented ALU, compare, load/store,
read-modify-write, transfer, stack, flag, branch and control-flow instructions,
including indexed-indirect, indirect-indexed and indirect-JMP forms. Operands
retain encoded fields and addressing syntax; available effects include A/X/Y,
stack/status-register dependencies, memory reads/writes, and direct branch,
call and jump targets. Indirect JMP intentionally has no invented direct
target in the decoder. Its lifted indirect target reads the low byte from the
encoded pointer and the high byte from the same page, wrapping `$xxFF` to
`$xx00` as on NMOS silicon. Image analysis can resolve this target only when
both pointer bytes are readable, file-backed, outside relocation-covered
bytes, and resolve into an executable segment. It records a reference to the
pointer slot and a validated target; it does not invent a direct target when
those conditions fail. Direct calls, jumps, returns and branches feed bounded
reachable-instruction analysis.

The twelve stable NMOS `KIL`/`JAM` opcodes (`$02`, `$12`, `$22`, `$32`,
`$42`, `$52`, `$62`, `$72`, `$92`, `$B2`, `$D2`, `$F2`) decode as one-byte
terminal traps. On NMOS silicon they lock instruction execution until reset;
the IR records terminal control flow but does not simulate the bus lock or
reset line. These bytes are distinct from their 65C02 `(zp)` instruction
meanings, which are not enabled in this NMOS profile.

The undocumented `DCP` decrement-then-compare family is decoded for its seven
NMOS forms: zero page, zero-page X, absolute, absolute X/Y, indexed-indirect,
and indirect-indexed. The instruction exposes read/write memory access, its
address-index dependencies, the accumulator read, and status-register write.
Typed lifting records the decremented byte, computes compare carry/zero/negative
flags, and retains the combined memory effect as a named intrinsic. Bus-cycle
details and variant behavior outside NMOS 6502 are not modeled.

The undocumented `SLO` (ASL then ORA), `RLA` (ROL then AND), and `SRE` (LSR
then EOR) families are decoded in their seven NMOS memory forms: indexed-
indirect, zero page, absolute, indirect-indexed, zero-page X, absolute Y, and
absolute X. They expose read/write memory effects, address-index dependencies,
the implicit accumulator/status dependencies, and their A/P register outputs.
Typed lifting retains the transformed memory byte and computes the combined
accumulator result and final N/Z/C flags: the shift/rotate supplies carry, and
the logical operation supplies N/Z. RLA's rotate input uses the incoming carry.
The combined memory write remains a named intrinsic because this IR does not
execute memory. Bus-cycle details and variant behavior outside NMOS 6502 are not
modeled.

The undocumented `RRA` (ROR then ADC) family is decoded for its seven NMOS
memory forms: indexed-indirect, zero page, absolute, indirect-indexed,
zero-page X, absolute Y, and absolute X. It reports read/write memory access,
address-index dependencies, incoming status carry, accumulator/status inputs,
and A/P outputs. Typed lifting rotates the memory byte right through the old
carry, feeds the rotated byte and the rotate's bit-zero carry-out into the
existing ADC arithmetic and flag formulas, and retains the memory write as a
named intrinsic. Decimal lifting follows the existing NMOS ADC formulas for
all accumulator and rotated operand bytes, including out-of-range BCD digits.
The decoder and lifter do not model bus cycles, intermediate
dummy writes, or chip-specific decimal-mode differences outside the modeled
NMOS behavior.

The undocumented `ISC` (increment memory then SBC) family is decoded for the
same seven NMOS memory addressing forms. It reports the memory read/write,
address-index and carry dependencies, and A/P outputs. Lifting increments the
memory byte with eight-bit wrap, then applies the existing SBC binary/decimal
flag formulas using the incoming carry; the memory write remains a named
intrinsic. Decimal correction handles all byte inputs. Bus cycles
and chip-specific decimal differences outside the modeled NMOS behavior are
not represented.

The undocumented `LAS` instruction is decoded in its NMOS absolute,Y form
(`0xbb`). It reads the indexed memory byte and incoming stack pointer, writes
the low byte of `memory & S` to A, X, and S, and sets N/Z while preserving the
other status bits. Typed lifting retains the shared value for all three
register outputs and a named read-only memory intrinsic. Other silicon
variants and bus timing are not modeled.

Remaining undocumented NMOS opcodes without an explicitly modeled effect,
including unstable multi-byte illegal operations, return `unsupported`.
`0x9C` and `0x9E` are supported as absolute and absolute,X STZ in the separate
65C02 mode; `$80` is BRA there. The decoder also supports STZ zero-page and
zero-page,X plus the eight `(zp)` ALU/load/store forms. Other 65C02 extensions
remain outside the decoder.
Truncated official instructions report `truncated`.

`evaluate_m6502_branch` computes the taken state for BPL/BMI, BVC/BVS,
BCC/BCS, and BNE/BEQ from the supplied processor status byte.
`evaluate_m6502_branch_instruction` additionally validates the decoded NMOS
6502 mode, conditional-flow kind, relative operand, direct target, and status
register read before evaluating. It returns only the decision; target
selection and program-counter updates remain the caller's responsibility.

The initial decompiler lift models direct loads and stores, logical and
arithmetic operations, compares, flag changes, register transfers, index
increments/decrements, conditional branches, and returns. TAX/TAY/TXA/TYA/TSX
and TXS now expose their exact byte register-copy outputs; all except TXS also
set N/Z from the transferred byte while preserving other status bits. INX/DEX/
INY/DEY expose wrapped eight-bit results and corresponding N/Z outputs in
parallel SSA definitions. CMP, CPX, and CPY
now express the eight-bit subtraction result's carry, zero, and negative
effects directly in the status-register assignment. BIT models its zero test
from `A & operand` and copies operand bits 6 and 7 into V and N while
preserving the other status bits. These expressions are tracked through
register SSA so later branches see the updated status version. Operations
whose detailed arithmetic or status behavior is not yet implemented remain
named `m6502_*` intrinsic calls; their input/output register and memory
effects are preserved. AND, ORA, and EOR now carry explicit parallel A/P output
formulas: A receives the byte operation, Z is set on a zero result, N copies
result bit 7, and all other status bits are preserved. CMP, CPX, and CPY keep
their explicit byte subtraction C/Z/N formulas. ADC and SBC also expose their
binary byte result and C/Z/N/V formulas, including carry-in and carry/no-borrow
behavior. Signed overflow in binary ADC is `~(A ^ M) & (A ^ R) & $80`;
in binary SBC it is `(A ^ M) & (A ^ R) & $80`, where `R` is the final
eight-bit result. The symbolic SBC lift uses the conjunction of both sign
conditions. `evaluate_m6502_binary_arithmetic` in
`libs/processors/include/hexlab/processors/m6502_semantics.hpp` provides a
pure evaluator for decoded ADC/SBC operands in binary and decimal modes. In
decimal mode it returns the adjusted accumulator and models NMOS C/Z/V/N
behavior for all byte inputs, including invalid packed-BCD digits; unsupported
opcodes return no result. The caller supplies the value read by
the instruction, so this function does not model addressing or bus cycles.
Because NMOS 6502 decimal mode is selected by P.D, the output formula
uses a status-dependent selection, so binary formulas are never applied
unconditionally to decimal-mode execution. Decimal ADC/SBC lifting now models
packed BCD correction for all byte inputs. ADC adjusts the low digit and
then the high digit; SBC propagates the low-digit borrow and applies decimal
correction to both digits. C records decimal carry/no-borrow. NMOS flags are
taken at different points: Z follows the pre-correction binary byte; ADC N/V
follow the intermediate value after low-digit correction and before high-digit
correction; SBC N/V follow the binary ALU subtraction result. The other status
bits are retained. Correction also yields the NMOS device result for
out-of-range nibbles; portable software should still supply packed-BCD digits,
the values described by the MOS programming manual. Stack pushes and pulls,
memory shifts/rotates, and
memory INC/DEC now lower to operation-specific intrinsics with explicit
status, stack-pointer, accumulator, and memory effects. PHA/PHP and PLA/PLP
carry explicit modulo-256 stack-pointer formulas and describe accesses in page
$0100. Their decoded instructions also report implicit stack memory writes
(PHA/PHP) or reads (PLA/PLP). PHP and BRK push P with B/U set; PLP restores
C/Z/I/D/V/N, preserves the internal pseudo-B bit, and fixes U. PLA sets N/Z
from its pulled byte while preserving the remaining status bits. Pulled bytes
remain unknown until memory execution is available. JSR records its exact PC+2 return bytes,
high byte then low byte, direct decoded target, and two-byte SP decrement.
RTS and RTI expose dynamic stack-derived return expressions, including page
$01 wrapping and RTS's increment of the pulled address. BRK records PC+2,
status push, stack decrement, and the $FFFE/$FFFF vector read; the vector target
remains unknown because it depends on runtime memory. These stack intrinsics
retain a named memory effect and explicit architectural register outputs. RTS
and RTI now emit an effectful page-$01 stack-read intrinsic before their
symbolic return; the PC bytes remain opaque, while S advances by two or three
with byte wrapping (RTI also restores masked P). The intrinsic records the
whole-memory dependency for SSA. The final PC target stays dynamic and is not
resolved from the interrupt vector or stack contents.
Hardware IRQ and NMI entry has a byte-level evaluator for an interrupt that
has already been accepted by the CPU. It pushes the interrupted PC high byte,
PC low byte, then P with B clear/U set; decrements S by three with byte wrap;
sets I while preserving the other NMOS status bits (including D); and selects
the IRQ ($FFFE) or NMI ($FFFA) vector supplied by the caller. It returns the
resolved target when the caller provides both vector bytes. This does not
model IRQ masking/recognition, NMI-vs-IRQ sampling priority, stack memory writes,
interrupt timing, reset entry, or cycle-by-cycle bus activity. The evaluator
does not infer an asynchronous interrupt from an instruction stream.
Accumulator and memory ASL/LSR/ROL/ROR now carry exact byte-result formulas
and parallel C/Z/N updates. Rotates consume the pre-instruction carry bit;
other status bits are preserved. Memory shifts/rotates and INC/DEC now declare
an explicit read/write memory effect in the IR, rather than an opaque unknown
effect. The SSA pass records both memory input and output versions and
conservatively invalidates memory partitions because the effective address is
not represented as a precise store. The memory value remains represented as a
load in the formulas; the IR now also records which intrinsic operand supplies
the exact byte written back to that same memory location. Pseudocode displays
this output alongside the register outputs. Whole-memory SSA still represents
the effect conservatively and does not forward this value to later loads or
partition the location. The IR does not claim bus-cycle timing or model the
NMOS 6502's intermediate dummy writes during read-modify-write instructions.
The modeled composite memory operations SLO, RLA, SRE, RRA, ISC, and DCP carry
the same explicit input/output pairing.
The NMOS undocumented ANC immediate aliases ($0B and $2B) decode as one
operation. Their lift ANDs the immediate byte into A, sets N and Z from the
result, copies result bit 7 into C, and preserves the other modeled status
bits. This describes architectural register effects; undocumented silicon
variants and bus-cycle details are not modeled.
The stable undocumented AXS/SBX immediate opcode ($CB) computes
`X = (A & X) - immediate` modulo 256, sets C when the intermediate unsigned
value `A & X` is at least the immediate, and sets Z/N from the resulting X;
other modeled status bits are preserved. The decoder records A/X reads and
X/P writes, and lifting retains the operation as a named intrinsic with those
exact output formulas. This is enabled only in the NMOS 6502 profile; the
65C02 assigns `$CB` to WAI, which remains outside this profile.
The NMOS undocumented ALR immediate opcode ($4B) computes `A = (A & immediate)
>> 1`; C receives bit 0 of the AND intermediate, while Z/N come from the
shifted accumulator and the other modeled P bits are preserved. Its evaluator
accepts only the decoded two-byte NMOS immediate form and reports the resulting
A/P values. It does not model bus cycles or claim behavior for CMOS variants.
The stable undocumented LAX family is decoded for indexed-indirect, zero-page,
absolute, indirect-indexed, zero-page,Y, and absolute,Y modes. Its fetched byte
is written to both A and X, and N/Z are updated from that byte while the other
modeled status bits are preserved. SAX is decoded for indexed-indirect,
zero-page, absolute, and zero-page,Y modes; it writes `A & X` to memory without
changing status. Their memory and address-register dependencies are explicit,
and both lifts retain exact register or memory outputs. These encodings are
NMOS-specific and are not enabled as a 65C02 instruction set.
The decoder attaches NMOS cycle-count metadata to every documented opcode.
`M6502Timing::base_cycles` is the minimum count; indexed memory reads set
`page_cross_penalty` when their effective address may cross a page, and
conditional branches separately record the taken and taken-plus-page-cross
penalties. Consumers can therefore calculate branch timing and indexed-read
timing after resolving runtime register values. The table follows the MOS
instruction-set summary. No cycle estimate is attached to unofficial opcodes
because this profile does not claim a chip-variant timing contract. This is
instruction-level clock metadata, not a cycle-by-cycle bus trace; it does not
model dummy reads/writes or interrupt sampling points. The 16-bit indirect JMP
expression is available to control-flow analysis, but the lifter does not
execute memory or simulate instruction cycles. Executable interrupt/vector
target resolution also remains incomplete.

The stable unofficial NMOS NOP encodings are decoded by their actual lengths
and addressing forms: implied, immediate, zero-page, zero-page indexed,
absolute, and absolute indexed. Immediate encodings retain their operand byte;
memory forms record an effective-address read and X reads where indexed. These
instructions do not claim register or status writes, including the DOP/TOP
memory-read variants. Unofficial NOP timing and dummy bus accesses remain
unmodeled, and overlapping bytes are interpreted according to the explicitly
selected NMOS profile rather than as 65C02 instructions. They use the existing
generic NOP presentation/lifting behavior; no separate value evaluator is
needed because the operation has no architectural result.

The behavior described here follows the [MOS Technology MCS6500 Programming
Manual](https://bitsavers.org/components/mosTechnology/6500-50A_MCS6500pgmManJan76.pdf)
and the [Visual6502 decimal-mode notes](https://visual6502.org/wiki/index.php?title=6502DecimalMode),
including the NMOS flag behavior that differs from 65C02 parts.


## Exact documented register loads

LDA, LDX, and LDY now have parallel typed value/status formulas for their
immediate, unindexed zero-page, and unindexed absolute encodings:

| Register | Immediate | Zero page | Absolute |
| --- | --- | --- | --- |
| A (`LDA`) | `$A9` | `$A5` | `$AD` |
| X (`LDX`) | `$A2` | `$A6` | `$AE` |
| Y (`LDY`) | `$A0` | `$A4` | `$AC` |

An immediate loads its encoded byte without a memory effect. Zero-page forms
read exactly the unsigned 8-bit address in page `$00`; absolute forms read the
encoded little-endian 16-bit address, including `$FFFF`, without interpreting
it as a signed displacement. The native decoder retains lengths, formatting,
encoded fields, timing and memory effects, and now reports the incoming P
read needed to preserve its unchanged bits. No index addition or pointer
fetch is inferred for these nine forms.

Each load writes its selected 8-bit register, sets Z exactly when the loaded
byte is zero, and copies bit 7 into N. C, I, D, V, and the internal modeled B/U
bits are preserved. Decimal mode does not change load behavior. The lifter
retains value and P outputs in one intrinsic with pre-instruction inputs and
uses the same memory byte in both formulas. Immediate N/Z bits come from the
processor helper; memory-backed N/Z remain symbolic until the byte is known.
Unexpected encodings, operand shapes, widths, or effects stay opaque.

`evaluate_m6502_load` provides the same value/status transformation for any
caller-fetched byte and LDA/LDX/LDY opcode; other opcodes return no result.
The caller selects the destination register and performs memory access. The
helper does not execute an addressing mode, modify CPU state, or simulate bus
cycles. Indexed and indirect load lifting remains opaque because native
zero-page pointer wrapping and 16-bit indexed address wrapping need a richer
address-expression representation. Interrupts/vector execution, cycle-level bus
behavior, and other 65xx families remain outside this slice. A separate W65C02
decoder mode recognizes eight zero-page-indirect ALU/load/store forms, BRA, and
STZ in zero-page, zero-page,X, absolute, and absolute,X modes. These forms
expose typed operands, branch or memory effects, and CMOS mnemonics. BRA has a
resolved 16-bit target; STZ is a memory write without a source-register
dependency. The indirect forms report the pointer fetch and format as `(zp)`.
No CMOS lifting or cycle timing is claimed. WAI, other CMOS instructions, and
reserved encodings are not yet implemented; the NMOS mode retains its
undocumented-opcode interpretations.
Load flag rules follow the MOS programming manual
linked above.

## Standalone compare and BIT evaluation

`evaluate_m6502_compare` evaluates CMP, CPX, CPY, and BIT once the caller has fetched the operand. Compare operations set carry from unsigned `left >= operand`, zero from equality, and negative from the wrapped 8-bit difference while preserving the other modeled status bits. BIT takes A as `left`, sets zero from `A & operand`, copies operand bits 7 and 6 into N and V, and preserves the remaining status bits. Unsupported opcodes return no result. The helper does not fetch memory or execute an addressing mode.

## Standalone shift and rotate evaluation

`evaluate_m6502_shift` evaluates ASL, LSR, ROL, or ROR for one already-fetched
byte. ASL/ROL shift bit 7 into carry; LSR/ROR shift bit 0 into carry. ROL
inserts incoming carry at bit 0, and ROR inserts it at bit 7. All forms update
N and Z from the result, set C from the shifted-out bit, and preserve the other
modeled P bits. Unsupported opcodes return no result. The helper does not
select A versus a memory operand, fetch or write memory, or model bus cycles.
These value/status formulas match the native lifter's documented accumulator
and memory RMW operation outputs; exact memory transaction timing remains
outside the model.

`evaluate_m6502_increment_decrement` evaluates byte `INC`/`DEC` and register
`INX`/`DEX`/`INY`/`DEY` with 8-bit wraparound. It updates only N and Z and
preserves carry and the remaining modeled P bits. The caller selects the
register or memory operand and performs any memory read/write; bus cycles and
RMW timing are not modeled.

`evaluate_m6502_transfer` evaluates `TAX`, `TAY`, `TXA`, `TYA`, `TSX`, and
`TXS` from a caller-supplied source byte. The first five update N/Z from the
transferred value and preserve the other modeled P bits. `TXS` transfers X to
the stack pointer without changing P. Register selection and state commit are
caller-owned.

`evaluate_m6502_binary_arithmetic_instruction` binds the existing ADC/SBC
helper to decoded immediate or byte-memory operand facts, and verifies that
the instruction reads A/P and writes A/P. The caller supplies current A/P and
the already fetched operand byte. Address calculation, bus behavior, and
committing the returned accumulator/status remain caller-owned.

`evaluate_m6502_status_stack_instruction` handles decoded `PHP` and `PLP`
status-byte conventions. PHP pushes a copy of P with B and the unused bit set;
PLP ignores the pulled B bit and forces the unused bit high in the returned P.
The adapter checks the decoder's stack/status register effects. The caller
still performs the stack read or write, updates S, and commits P.

`evaluate_m6502_accumulator_stack_instruction` handles decoded `PHA` and
`PLA`. PHA returns A as the byte to push and preserves A/P; PLA returns the
pulled byte as A and updates only N/Z. The adapter checks the decoded stack,
accumulator, and status effects. Stack memory access, S updates, and state
commit remain caller-owned.

`evaluate_m6502_return_instruction` handles decoded `RTS` and `RTI` from
caller-fetched bytes in pop order. RTS forms the stacked address and adds one;
RTI restores the exact stacked address and normalizes P by clearing B and
setting the unused bit. Both return the wrapped 8-bit stack pointer after the
two or three pops. Stack reads and state commit remain caller-owned.

`evaluate_m6502_flag_control_instruction` evaluates `CLC`, `SEC`, `CLI`,
`SEI`, `CLV`, `CLD`, and `SED`. Each form updates only its selected C, I, V,
or D bit and preserves all other modeled P bits. The adapter validates the
decoded P read/write effects; committing the returned status remains
caller-owned.

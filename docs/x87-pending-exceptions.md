# Caller-owned x87 pending exception delivery

`evaluate_x87_pending_exception` takes an x87 control word, status word, and
the caller's CR0.NE mode. It intersects the six sticky FSW exception flags
(IE/DE/ZE/OE/UE/PE, bits 0 through 5) with the inverse FCW mask bits. A
nonzero result is pending at the next waiting x87 operation or WAIT/FWAIT.
The helper returns the active exception-flag mask, a status word with ES and B
set for the pending delivery, and either native `#MF` or legacy external
IRQ13 selection. Existing sticky flags and all unrelated status bits are
preserved. The helper does not raise a host exception, dispatch a handler, or
simulate the external interrupt controller.

The decoder marks waiting x87 instructions explicitly and marks the
FN-prefixed non-waiting control/environment operations as non-waiting. Waiting
forms expose status/control reads. The decompiler adds a may-trap edge with a
symbolic `x87_pending_unmasked_exception(FSW, FCW)` condition before each
waiting instruction. This edge represents delivery of an earlier pending
exception; it does not claim to evaluate exceptions generated by the current
operation.

`retire_x87_stack_state` composes this pending check with the caller's result
from a supported operation evaluator. A waiting operation does not advance
TOP or tags when a prior exception is pending, and any operation whose
caller-owned evaluation reports `completed == false` leaves stack state
unchanged. Completed operations use the existing exact TOP/tag transfer for
their decoded push/pop/free/swap effects. The normal-transfer API remains
available to callers that already know the instruction retired.

`evaluate_x87_stack_fault` handles the status-word portion after a caller has
detected stack overflow or underflow from tag state. It sets sticky IE and SF,
sets C1 for overflow or clears it for underflow, then resolves unmasked
delivery through the existing pending-exception helper. A masked invalid
exception reports `instruction_completed=true`; the caller remains responsible
for the instruction's indefinite result and stack/tag behavior. An unmasked
fault reports `instruction_completed=false`, so callers can preserve the prior
stack state with `retire_x87_stack_state`.

Current limits are deliberate: this does not model processor/task-switch
delivery, FERR#/IRQ13 wiring, signal/handler execution, automatic stack
condition detection, operation-specific indefinite values, or pending exceptions produced by all x87
instruction families. Numeric evaluators report completion/status for their
documented supported operations; other decoded instructions remain opaque.
See [the Intel SDM, x87 exception handling](https://cdrdv2-public.intel.com/825743/325462-sdm-vol-1-2abcd-3abcd-4.pdf)
for the native #MF and legacy external-delivery modes.

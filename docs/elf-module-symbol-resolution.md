# ELF supplied-module symbol resolution

`hexlab_cli modules <binary>...` reports a bounded symbol-level ELF resolution pass after the dependency inventory and PE import report. It considers only the explicitly supplied files; it never opens a `DT_NEEDED` path or invokes the host dynamic loader.

The pass treats undefined non-local symbols in non-section symbol tables as imports. Candidate providers must be ELF inputs supplied on the command line and, when the importer has `DT_NEEDED` entries, have a basename named by one of those entries. Matching uses the exact base symbol name. A versioned import requires an export with the exact GNU version name. An unversioned import can match an unversioned export or the default (non-hidden) version of a versioned export. Hidden and internal exports are excluded; protected exports remain eligible to external importers. Local exports are excluded. Exactly one matching symbol resolves; no match is unresolved and multiple matches are ambiguous. Each importer is capped at 100,000 rows.

This is metadata matching, not a runtime loader simulation. It does not apply relocations, choose among ELF search-path precedence or symbol interposition rules, model namespaces/auditing, or infer providers when no supplied file is named by `DT_NEEDED`. Symbol type compatibility, IFUNC execution, TLS allocation, copy relocations, weak-zero fallback, and architecture-specific ABI rules are not modeled. The report prints a file address only when the loader recorded one; it does not imply that address is a process runtime address. Inputs without parsed ELF dynamic symbol tables can have no rows to resolve.

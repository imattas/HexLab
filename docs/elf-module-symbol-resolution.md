# ELF supplied-module symbol resolution

`hexlab_cli modules <binary>...` reports a bounded symbol-level ELF resolution pass after the dependency inventory and PE import report. It considers only the explicitly supplied files; it never opens a `DT_NEEDED` path or invokes the host dynamic loader.

The pass treats undefined non-local symbols in non-section dynamic symbol tables as imports. Candidate providers must be ELF inputs supplied on the command line and, when the importer has `DT_NEEDED` entries, have a basename named by one of those entries. A candidate provider must have the same ELF class, byte order, and machine as the importer; a supplied name match from an incompatible object is reported as unsupported. Provider exports are read only from symbol tables referenced by the provider's dynamic tables, so a definition present only in a static symbol table cannot satisfy a dynamic import. Matching uses the exact base symbol name. A versioned import requires an export with the exact GNU version name and, when present, the `DT_VERNEED` library basename. An unversioned import can match an unversioned export or the default (non-hidden) version of a versioned export. Hidden and internal exports are excluded; protected exports remain eligible to external importers. Global, weak, and GNU-unique exports are eligible, including absolute definitions; local and other binding classes are excluded. Exactly one matching symbol resolves; no match is unresolved and multiple matches are ambiguous. Each importer is capped at 100,000 rows.

This is metadata matching, not a runtime loader simulation. It does not apply relocations, choose among ELF search-path precedence or symbol interposition rules, model namespaces/auditing, or infer providers when no supplied file is named by `DT_NEEDED`. The compatibility check covers ELF class, byte order, and machine only; OSABI, ABI flags, and ordinary symbol type compatibility are not modeled. A matching TLS or GNU IFUNC export is reported unsupported because resolving it requires runtime allocation or resolver execution. Copy relocations and weak-zero fallback are also not modeled. The report prints a file address only when the loader recorded one; it does not imply that address is a process runtime address. Inputs without parsed ELF dynamic symbol tables can have no rows to resolve.

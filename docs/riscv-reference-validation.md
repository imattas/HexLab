# RISC-V data-reference validation

Decoded references support bounded RV32/RV64 address propagation. LUI seeds a sign-extended U-immediate value, and AUIPC seeds its signed U-immediate relative to its own PC. ADDI may add a signed immediate to a tracked register, while ORI applies its sign-extended immediate with XLEN-width bitwise OR; these values can flow across recovered CFG edges. ADDI with `x0` can seed an absolute immediate. At a join, a value survives only if every predecessor proves the same address. Address facts may remain outside mapped segments while being built, but a typed `memory_address` reference is emitted only for a mapped target.

A later load or store using that tracked register resolves to the computed effective address. The target must remain inside a single mapped segment for the full access width, and the segment must have the required read or write permission. Invalid or permission-incompatible memory operands remain typed unresolved expressions. JALR calls and jumps resolve when their register-relative base is known and the resulting low-bit-cleared address is in an executable segment. Source instructions are already required to lie wholly in executable code according to the image code policy. Resolved references participate in the same indexed incoming/outgoing pages and canonical reference cache as other references.

The implementation drops a value when its register is overwritten and clears all propagated values across calls. It does not evaluate general register-register arithmetic, preserve facts through cyclic or incomplete predecessor graphs, or resolve ELF/Mach-O relocation pairs for data references. A CFG join requires exact predecessor agreement; unknown entry paths contribute no facts.

`tests/reference_tests.cpp` exercises literal RV32 and RV64 AUIPC+ADDI/load/store instruction bytes, address formation and effective addresses, data-segment indexing, writable/readable permission rejection, unmapped targets, non-executable source rejection and reference-index roundtrips. Cross-block predecessor agreement and JALR resolution are newly implemented and still need focused regression fixtures. The reference-cache engine version is unchanged because the serialized reference schema and identity rules are unchanged.

# PDB container support

HexLab parses the bounded MSF 7.0 container used by modern Windows PDB files. It validates the superblock, directory block map, stream block lists, file extents, stream counts and aggregate allocation budget, and observes cancellation between block reads. It exposes the stream table plus the version, signature, age and GUID from PDB stream 1 so a caller can match a CodeView identity before consuming debug data.

PE parsing also extracts RSDS CodeView GUID, age, path, and both debug-directory and raw-record source locations. This makes the association inspectable while preserving the boundary between identity matching and importing PDB types.

`LF_TYPESERVER2` records are decoded into their GUID, age, and path. `resolve_pdb_type_servers` asks a caller-supplied resolver to load each referenced PDB, checks the returned PDB identity against the exact GUID+age pair, and returns each server TPI as its own namespace. The resolver has a caller-set server count bound (maximum accepted bound 255), cancellation is observed during discovery, duplicate identities are coalesced, and conflicting paths fail.

`parse_pdb_type_server_map` reads the DBI Type Server Map substream and assigns local namespace selectors by TSM entry ordinal; `tiBase` is retained as the server's type-index base and is not used as the selector. Ordinal zero is reserved for the requesting PDB's own TPI, so the first entry is treated as a sentinel and is neither resolved nor identity-checked. Nonzero entries are resolved through the caller callback and each opened PDB is checked against the DBI signature+age. Duplicate signatures/ages are coalesced and each local selector is mapped to a distinct global TPI namespace. Nested maps are flattened with the same identity checks, path-conflict check, count and depth limits. `resolve_pdb_type_graph(root, servers)` combines the root and server TPI graphs and retains each source and target namespace on cross-PDB references, with a two-million combined-record limit and four-million combined-edge limit. The legacy DBI map carries a 32-bit signature rather than an RSDS GUID.

The desktop PDB type importer resolves adjacent sidecar PDBs by filename only, limits each sidecar to 128 MiB and aggregate sidecar bytes to 512 MiB, and verifies identity before import. It tries the combined root/server graph before a root-only import so valid cross-namespace references do not fail prematurely. If a server is missing or fails identity validation, unresolved types that depend on that external namespace are skipped while unrelated root TPI types remain importable; unresolved references within their own TPI remain errors. If no DBI server namespace is present, the desktop retains the legacy `LF_TYPESERVER2` sidecar path. It skips conflicting names and reports server failures without following paths outside the selected PDB directory. Other callers should constrain filesystem/network lookup and byte budgets inside their resolver.

`parse_pdb_types` decodes a bounded TPI subset (see [PDB TPI type parsing](pdb-types-validation.md)). `parse_pdb_symbols` reads the DBI module list and module symbol substreams, importing `S_GPROC32`/`S_LPROC32` procedure records and `S_GDATA32`/`S_LDATA32` data records. It also scans the DBI `SymRecordStream` for `S_PUB32`, `S_GPROC32`, and `S_GDATA32`. `S_PROCREF`, `S_LPROCREF`, and `S_DATAREF` are resolved by exact one-based module index and module-stream byte offset to an already parsed procedure or data record; they are not guessed by name. A resolved row carries the global reference spelling and origin plus both the target module record identity and the reference record kind/offset. These rows retain their source (module or global stream), public status, CodeView spelling, section number and section-relative offset, procedure size when present, module and object names when present, module index, record kind, and record offset within their source stream. `parse_pdb_locals` walks module procedure scopes and imports `S_LOCAL` locals/parameters plus legacy `S_BPREL32` and `S_REGREL32` frame/register-relative entries. It attaches following `S_DEFRANGE_REGISTER`, `S_DEFRANGE_FRAMEPOINTER_REL`, `S_DEFRANGE_FRAMEPOINTER_REL_FULL_SCOPE`, and `S_DEFRANGE_REGISTER_REL` records to the preceding local. Each supported defrange retains its location kind, register or frame offset, section-relative start and extent, and encoded gap list. Local rows also retain their procedure's section-relative start and size, type index, parameter flag, module/object provenance, lexical-scope membership by owning procedure, and record identity. PE binding maps the owning procedure start to an address only after exact PDB GUID+age matching and PE section/image bounds checks. Unknown length-delimited symbol kinds are skipped.

Symbol and procedure starts deliberately remain section-relative in the PDB parser: consumers must match section numbers to the PE image's section table before deriving an RVA. The defrange subset leaves `S_DEFRANGE` and `S_DEFRANGE_SUBFIELD` DIA expressions, `S_DEFRANGE_SUBFIELD_REGISTER`, and `S_DEFRANGE_REGISTER_REL_INDIR` uninterpreted; locals with only these forms keep unknown locations. Lexical block nesting is not exposed as a separate tree; locals are associated with their containing procedure. Global references with a zero or out-of-range module, missing target offset, or target record of the wrong symbol kind fail as malformed instead of being rebound by spelling. The reader still does not decode public/global hash tables or the full CodeView symbol vocabulary. Module/object names are provenance only and are not guaranteed to be source file paths. Parsing is capped at two million imported rows, bounded by the MSF stream limits, and checks cancellation between records.

Run `hexlab_pdb_tests` (CTest name `pdb_types`) for valid stream mapping, identity extraction, module/global/public/local/parameter symbol extraction, and malformed-container/record bounds. The MSVC-only `pdb_msvc_artifact` check also exercises locals from the generated PDB artifact.

Format reference: [LLVM MSF 7 format](https://llvm.org/docs/PDB/MsfFile.html), [PDB information stream](https://llvm.org/docs/PDB/PdbStream.html), [DBI stream](https://llvm.org/docs/PDB/DbiStream.html), and [CodeView symbols](https://llvm.org/docs/PDB/CodeViewSymbols.html).


S_FRAMEPROC summary records attach to their owning module procedure and carry the reported frame size, padding size/offset, total saved-register byte count, exception-handler section/offset, and raw flags through to the matched PE PDB symbol metadata. The parser does not derive unwind rules or identify which registers occupy the save area; global-stream symbols and procedures without S_FRAMEPROC have no frame summary. Inline scopes now retain bounded explicit-length binary-annotation ranges and join C13 InlineeLines definition start lines through module/IPI/file identities into PE inspection, Source navigation, and debugger source text. Unknown opcodes/signatures and separated-code-chunk bases stay explicit; implicit lengths and caller call-expression attribution remain unsupported. See [inline-site provenance](pdb-inline-site-local-provenance.md) for the supported slice and limits. This extension requires serial compile validation; no new tests or builds were run during its implementation.

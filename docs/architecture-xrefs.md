# Architecture-derived references

The reference index derives a numeric target only when instruction operands or a conservative register-value chain prove it and the complete target byte range is mapped with the required permissions. Calls, unknown writes, disagreeing control-flow inputs and unsupported expressions do not produce speculative targets.

## x86-64

Full-width `MOV` immediates and register copies, RIP-relative or register-based `LEA`, and immediate/register `ADD` and `SUB` propagate address facts through recovered basic blocks using x64 word-width arithmetic. Selected 32-bit GPR writes are modeled with the architectural zero-extension to the parent register: `MOV`, `LEA`, `ADD`, `SUB`, `XOR`/`SUB` self-zeroing, plus register-source `MOVZX`/`MOVSX`. Narrow-source extension reads the exact low or high-byte alias from a previously proven full-register value. A value reaches a join only when every predecessor proves the same value; incomplete cyclic inputs are not used. Register-based memory operands resolve when the full access range has the required mapping and permissions. A 64-bit load may also provide a value for a later indirect call or jump when its pointer slot is readable and the resulting target is executable. Slots covered by a relocation or dyld fixup are not read from stale file bytes. Unknown calls invalidate caller-saved integer facts. Other partial-width writes and unsupported arithmetic invalidate the affected register without producing a target; unknown calls and unproven merge inputs remain unresolved.

## Flat x86-32

The same conservative propagation applies in non-segmented x86-32 functions, using 32-bit register and address arithmetic. Full-width `MOV` immediates/copies, absolute or register-based `LEA`, and immediate/register `ADD` and `SUB` can form addresses across recovered basic blocks. Joins require every available predecessor to agree; incomplete cyclic inputs do not prove values. Readable 32-bit pointer slots may resolve an indirect call or jump when the loaded destination is executable. A call clears the entire tracked register state because the active 32-bit calling convention is not known. Segmented contexts, segment overrides, address-size combinations that cannot be represented by the flat image map, and 16-bit near/far pointer semantics remain unresolved.

## RISC-V

RV32/RV64 `LUI` and `AUIPC` seeds and XLEN-width `ADDI`/`ORI`/`XORI`/`ANDI` arithmetic propagate across recovered basic blocks only when predecessor states agree. Register `ADD`, `SUB`, `XOR`, `OR`, and `AND` propagate when both inputs are proven address values or architectural zero; RV64 `ADDW`/`SUBW` apply their 32-bit wrap and sign extension. Resulting values can continue through later arithmetic even when an intermediate value is not mapped, while an immediate reference is emitted only when the exact result maps in the instruction's address space. Immediate `SLLI`, `SRLI`, and `SRAI` and register-count `SLL`, `SRL`, and `SRA` transform a known value using the ISA-masked shift count and XLEN wrap/sign rules. RV64 word shifts (`SLLIW`/`SRLIW`/`SRAIW` and `SLLW`/`SRLW`/`SRAW`) compute in 32 bits and sign-extend the result to XLEN. Shift-count and source provenance is retained for register-count forms. Bitwise-immediate arithmetic applies signed 12-bit immediates and XLEN wrap as decoded. Register-relative memory operands resolve for mapped ranges. Integer loads that read one full XLEN-sized pointer from a readable, file-backed slot may seed the destination register when the loaded value maps into the image; later base-relative accesses can then produce references. For ELF64 little-endian RISC-V, a narrow relocation-pair path recognizes adjacent 4-byte `PCREL_HI20`/`PCREL_LO12_I` fields on `AUIPC` followed by `ADDI`, when the LO symbol is a defined local symbol exactly naming the HI place, the HI/LO match is unique, and the decoded registers agree. The resolved target is the HI relocation's defined symbol plus its explicit addend. LO12_S, interposed or undefined symbols, RV32, compressed instructions, non-adjacent pairs, other low instructions, and ambiguous or incomplete metadata remain unresolved. Standalone RISC-V PC-relative HI/LO relocations are never treated as ordinary scalar relocations. This does not interpret relocation-covered or runtime-populated pointer slots, narrower loads, floating-point loads, or unknown call effects. `JALR` target resolution retains the existing known-base, low-bit-clear, executable-target checks.

Zba `SH1ADD`/`SH2ADD`/`SH3ADD` and their `.UW` forms propagate when both source values are proven; `.UW` zero-extends the low 32 bits of `rs1` before shifting, and sums wrap at XLEN. `ADD.UW` and `SLLI.UW` also propagate for RV64 with their zero-extension and encoded shift semantics. Producer provenance includes contributing input chains.

## AArch64

`ADR` and `ADRP` operands retain their decoded address. Integer `LDR` literal forms for W/X destinations and `LDRSW` resolve the signed imm19 scaled by four relative to the current instruction address (A64 has no PC bias or alignment adjustment); xref source and operand identity remain attached to the literal memory operand. SIMD/FP literal loads and `PRFM` remain unsupported. `MOVZ` and `MOVN` seed known integer values, and `MOVK` updates one 16-bit lane only when the prior destination value is known. Their mapped results receive an immediate reference at the instruction that produced that value. Immediate `ADD`/`SUB` on matching `W` registers uses 32-bit wraparound and zero-extends the result; matching `X` registers use the existing bounded 64-bit address arithmetic. The unshifted register forms also propagate when both source registers hold proven values, and only when the decoder supplies exactly three operands (no explicit shift immediate): `W` results wrap at 32 bits, while `X` addition/subtraction rejects overflow or underflow. Values flow across recovered basic-block edges when every predecessor is available, and at merges a value survives only when all predecessor states agree. A load or store with a tracked base resolves only to a mapped range with the required permissions. Register-offset forms also resolve when the index register is independently proven: UXTX/UXTW/SXTX/SXTW extension and the encoded element-size shift are applied at 64 bits with checked underflow and overflow. A 64-bit `LDR` may also seed its destination from a full pointer stored in a readable, file-backed slot when the loaded value maps into the image. Stack-pointer/zero-register operands, shifted register arithmetic, invalid wide-move shifts, unknown `MOVK` inputs, indexed forms with unknown or unsupported index values, disagreeing or cyclic-incomplete inputs, and out-of-range expressions remain unresolved. Relocation-covered and runtime-populated pointer slots are not read as constants.

## A32 and Thumb

PC-relative `LDR` and related instructions with a decoded absolute effective address produce data references. This includes Thumb literal loads, whose decoder aligns the PC base as required by the encoding. Across recovered basic-block edges, A32 `ADD`/`SUB` immediate address formation from PC (PC+8) and Thumb `ADR` seed a register value; immediate `ADD`/`SUB` can carry that value forward. At joins, a value survives only when every predecessor provides the same address. Calls, cyclic or incomplete predecessor graphs, and A32/Thumb state changes clear facts. Loads and stores through a tracked base resolve only when the full access range is mapped with the needed permissions. Immediate and statically shifted register offsets (`LSL`, `LSR`, `ASR`, and nonzero `ROR`) are evaluated at 32 bits; pre-index and post-index effective addresses are distinguished, and a proven writeback updates the tracked base for following instructions. Dynamic shifts, `RRX` without a proven carry, multi-register transfers, and arbitrary arithmetic remain unsupported.

Unconditional A32/Thumb `MOV`, `MVN`, `AND`, `EOR`, `ORR`, `BIC`, `ADD`, `SUB`, and `RSB` data-processing forms now propagate a destination when their source values are proven. Operand2 may be an immediate, a proven GPR, or a statically/proven-register shifted GPR using `LSL`, `LSR`, `ASR`, `ROR`, or `RRX`; each shift is evaluated with the architecture's 32-bit rules. `RRX` and carry-dependent `ADC`/`SBC`/`RSC` resolve only when carry and all source values are proven. Predicated writes invalidate their destination facts instead of being assumed to execute, while their encoded immediate references remain available. The resulting address definitions retain the producing instruction for reference provenance. This follows the same constant-propagation approach used by Ghidra's [ARM analyzer](https://github.com/NationalSecurityAgency/ghidra/blob/master/Ghidra/Processors/ARM/src/main/java/ghidra/app/plugin/core/analysis/ArmAnalyzer.java), while HexLab additionally requires predecessor agreement and validates each target's execution-mode mapping.

In A32 data-processing operations, a decoded PC source or Operand2 PC is evaluated as the instruction address plus eight. This allows otherwise supported operations such as `MOV pc, pc` and logical/arithmetic PC writes to resolve when their other inputs are known. Thumb register reads of PC remain unresolved here because their alignment and bias depend on the instruction encoding.

Known register-derived writes to PC now resolve control references for A32/Thumb `BX`/`BLX`, data-processing writes such as `MOV`/`MVN` and supported arithmetic/logic operations, `LDR pc`, and `LDM`/Thumb `POP` when the loaded PC slot is statically available. For data-processing PC writes, an unknown A32 condition or Thumb IT predicate does not suppress the possible target xref when the predicate metadata is valid and the pre-instruction operands (including carry where needed) uniquely determine the destination. That uncertain instruction never advances the register facts used on later paths. `ArmExchange` and target-context metadata select Thumb versus A32 and apply the corresponding alignment before checking executable mappings. Exchange targets with low bits `10` are left unresolved because that A32 target encoding is unpredictable. This includes bit-zero interworking for valid exchange/load/ALU writes and Thumb-state retention for non-exchange writes. Resolved control references retain the proven target mode in the reference payload, and the desktop reference list shows `[A32]` or `[Thumb]`; following the address uses the image's validated target context. Reference payload v16 adds this field and rekeys older cached records on load. LDM/POP references attach to the register-list operand containing PC. The analyzer does not read relocation-covered pointer slots or infer values through runtime memory or unresolved register inputs.

## MIPS32

The analyzer tracks address values formed by `LUI`, followed by immediate `ADDI`, `ADDIU`, or `ORI`. Facts flow across recovered basic-block edges when every predecessor is known, and a register survives a merge only when all predecessor values agree. Loads and stores through that base plus the decoded displacement produce references only when the full data range is mapped with suitable read/write permission. An `LW` may also seed its destination from a full pointer stored in a readable, file-backed slot when the loaded value maps into the image; relocation-covered and runtime-populated slots are not interpreted. GPR zero is never treated as a writable address register. Proven, aligned `JR`/`JALR` values resolve only inside executable mapped segments. Cyclic or incomplete predecessor graphs do not contribute speculative incoming values; unsupported register-indirect control flow preserves its typed expression.

## MIPS64

MIPS64 address facts use the decoded 64-bit GPR width. `LUI` sign-extends its 32-bit result; `DADDIU` and `ORI` extend or combine a known base, and fixed `DSLL`/`DSLL32` shifts carry a proven value. The word-width `ADDI`/`ADDIU` forms are propagated only from sign-extended 32-bit inputs; `ADDI` must not overflow and `ADDIU` wraps at 32 bits before sign extension. `LD` and `SD` base-plus-displacement operands resolve only when the full 8-byte access has the required mapping and permission. A full-width `LD` may seed its destination from a readable, file-backed pointer slot with no overlapping relocation. `JR`/`JALR` resolve only when the tracked value is four-byte aligned and points into an executable mapped segment. MIPS64 width is never inferred from an MIPS32 fact; unsupported arithmetic, unknown call effects, and conflicting or incomplete CFG inputs discard facts.

## PowerPC

PPC32/PPC64 facts use the active mode's exact GPR and address width. `ADDI`/`ADDIS` form an address from a tracked base or the architectural zero base; `ORI`/`ORIS` combine an immediate with a tracked source. Register `ADD` and `SUBF` propagate only when both full-width inputs are known in the current address space; results use the active 32- or 64-bit wrap semantics (`SUBF` computes RB minus RA). Values flow through the existing bounded CFG must-analysis and survive joins only when predecessor values agree. D-form and indexed memory operands use the decoded base, index, scale, and signed displacement; update forms write the proven effective address back to the base register. Memory references require the full operand data width to be mapped with the required permission. A full-width `LWZ` in PPC32 or `LD` in PPC64 may seed the destination from a readable, file-backed pointer slot when the target maps into the image and no relocation covers the slot. Narrow loads, indexed expressions with an unknown register, mismatched widths, relocation-covered slots, calls, and disagreeing control-flow values remain unresolved.

## NMOS 6502

Absolute unindexed memory operands produce read, write, or read/write references according to the instruction effect. Indexed expressions remain unresolved when the effective address depends on runtime register values. `JMP ($addr)` reads its two-byte pointer from readable, file-backed memory only when neither byte overlaps relocation data; the decoded reference points to the pointer slot, while the jump reference points to the destination only when it is mapped executable code. The NMOS page-boundary behavior is modeled: a pointer at `$xxFF` reads its high byte from `$xx00`. `JMP` and `JSR` absolute forms retain their decoded direct targets. Runtime-written pointers, relocation-covered pointer bytes, unmapped operands, and non-executable destinations remain unresolved.

## Conservative boundaries

For all supported architecture families, permission failures and incomplete target ranges remain unresolved. Unsupported addressing modes, runtime-dependent registers, and unresolved pointer values retain their expression where available instead of generating speculative incoming references.

## Querying data objects

`ReferenceIndex::incoming_range` and `hexlab_cli project references --direction incoming --size N` return references whose numeric target or resolved association lies within the half-open VA range `[--at, --at + N)`. This lets a data object query find references to interior bytes, such as a field or a string element, while retaining normal reference-kind and provenance details. Range queries are bounded to one address space and reject empty or overflowing ranges; outgoing queries remain instruction-address based. Range pages de-duplicate overlapping targets with a row-index bitmap instead of a match-sized temporary, so the de-duplication workspace is capped at about 489 KiB by the four-million-reference index limit; returned rows remain capped at 4,096 and ordered by the reference index's stable row order. The index stays immutable and range queries add no persistent result cache; project consumers keep their existing `AnalysisKey` checks for input, byte revision, and decision revision before using an index.

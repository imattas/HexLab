# Architecture-derived references

The reference index derives a numeric target only when instruction operands or a conservative register-value chain prove it and the complete target byte range is mapped with the required permissions. Calls, unknown writes, disagreeing control-flow inputs and unsupported expressions do not produce speculative targets.

## Shared decoded memory effects

Some processor backends provide memory effects at instruction level while
leaving the one explicit memory operand marked as an address operand. For a
fallthrough instruction with exactly one decoded memory operand, no stack
value effect, and an explicit read and/or write memory flag, reference
classification now uses those flags to report a memory read, write, or
read/write. This shared rule covers decoded single-operand memory operations
such as ARM exclusive accesses and PowerPC forms while retaining the same
address calculation, relocation provenance, access width, and full-range
mapping checks. Instructions with multiple memory operands, control-flow
operations, implicit stack effects, or no memory effect flags keep their
operand-provided classification. NMOS 6502 keeps its separate indirect-pointer
semantics. Derived-cache version 92 invalidates old rows so the reference kind
is recomputed from the current instruction effects.

## x86-64

Full-width `MOV` immediates and register copies, RIP-relative or register-based `LEA`, and immediate/register `ADD` and `SUB` propagate address facts through recovered basic blocks using x64 word-width arithmetic. A `MOV` immediate into a full-width GPR also produces an address xref when the resulting value names mapped image bytes; this is a useful pointer heuristic, so integer constants that happen to fall inside a mapped segment can produce false-positive address xrefs. Selected 32-bit GPR writes are modeled with the architectural zero-extension to the parent register: `MOV`, `LEA`, `ADD`, `SUB`, `XOR`/`SUB` self-zeroing, plus register-source `MOVZX`/`MOVSX`. Narrow-source extension reads the exact low or high-byte alias from a previously proven full-register value. A value reaches a join only when every predecessor proves the same value; incomplete cyclic inputs are not used. Register-based memory operands resolve when the full access range has the required mapping and permissions. A 64-bit load may also provide a value for a later indirect call or jump when its pointer slot is readable and the resulting target is executable. Slots covered by a relocation or dyld fixup are not read from stale file bytes. Unknown calls invalidate caller-saved integer facts. Other partial-width writes and unsupported arithmetic invalidate the affected register without producing a target; unknown calls and unproven merge inputs remain unresolved.

A native `call` through an exact RIP-relative 64-bit memory operand can also establish a local call edge when its pointer slot is readable, non-writable, initialized, file-backed, and relocation-free, and the stored address names initialized executable code in the same x64 context. The decoded displacement field and the full eight-byte slot are checked against relocation/fixup metadata; import slots continue through the separate external-identity path, including ambiguous import slots that must not be reinterpreted as local pointers. The slot bytes are recorded as an instruction dependency so incremental edits invalidate and rediscover the edge. Other indirect call forms, writable or relocated/runtime slots, and targets outside the validated code mapping remain unresolved.

## Flat x86-16

For a non-segmented 16-bit image, the bounded x86 value analysis tracks full-width `MOV`, `LEA`, immediate/register `ADD` and `SUB`, and narrow `MOVZX`/`MOVSX` sources. Arithmetic wraps at 16 bits. Proven register-relative memory operands and readable 16-bit pointer slots can produce mapped data references and executable indirect call/jump targets; immediate moves produce address references only when the result maps into the image. CFG joins require all available predecessors to agree, and calls clear tracked registers because no 16-bit calling convention is assumed. Real/protected-mode segment bases, segment overrides, far pointers, and contexts marked `segmented_memory` remain unresolved. This flat mode is intended for images whose addresses are already represented in one image address space.

## Flat x86-32

The same conservative propagation applies in non-segmented x86-32 functions, using 32-bit register and address arithmetic. Full-width `MOV` immediates/copies, absolute or register-based `LEA`, and immediate/register `ADD` and `SUB` can form addresses across recovered basic blocks. A full-width `MOV` immediate produces an address xref only when its result lies in mapped image bytes; scalar constants that coincide with mapped bytes can be false positives. Joins require every available predecessor to agree; incomplete cyclic inputs do not prove values. Readable 32-bit pointer slots may resolve an indirect call or jump when the loaded destination is executable. A call clears the entire tracked register state because the active 32-bit calling convention is not known. Segmented contexts, segment overrides, and address-size combinations that cannot be represented by the flat image map remain unresolved.

## RISC-V

RV32/RV64 `LUI` and `AUIPC` seeds and XLEN-width `ADDI`/`ORI`/`XORI`/`ANDI` arithmetic propagate across recovered basic blocks only when predecessor states agree. Register `ADD`, `SUB`, `XOR`, `OR`, and `AND` propagate when both inputs are proven address values or architectural zero; RV64 `ADDW`/`SUBW` apply their 32-bit wrap and sign extension. Resulting values can continue through later arithmetic even when an intermediate value is not mapped, while an immediate reference is emitted only when the exact result maps in the instruction's address space. Immediate `SLLI`, `SRLI`, and `SRAI` and register-count `SLL`, `SRL`, and `SRA` transform a known value using the ISA-masked shift count and XLEN wrap/sign rules. RV64 word shifts (`SLLIW`/`SRLIW`/`SRAIW` and `SLLW`/`SRLW`/`SRAW`) compute in 32 bits and sign-extend the result to XLEN. Shift-count and source provenance is retained for register-count forms. Bitwise-immediate arithmetic applies signed 12-bit immediates and XLEN wrap as decoded. Register-relative memory operands resolve for mapped ranges. Integer loads that read one full XLEN-sized pointer from a readable, file-backed slot may seed the destination register when the loaded value maps into the image. RV64 `LWU` seeds its 64-bit destination from a readable file-backed 32-bit slot when the zero-extended value maps into the image and no relocation overlaps the slot. RV64 `LW` also seeds its 64-bit destination when a readable file-backed 32-bit slot, sign-extended to XLEN, maps into the image. Both 32-bit pointer-slot forms reject overlapping relocations; other narrow loads do not receive this pointer heuristic. Later base-relative accesses can then produce references. For ELF64 little-endian RISC-V, a narrow relocation-pair path recognizes adjacent 4-byte `PCREL_HI20`/`PCREL_LO12_I` fields on `AUIPC` followed by `ADDI`, when the LO symbol is a defined local symbol exactly naming the HI place, the HI/LO match is unique, and the decoded registers agree. The resolved target is the HI relocation's defined symbol plus its explicit addend. LO12_S, interposed or undefined symbols, RV32, compressed instructions, non-adjacent pairs, other low instructions, and ambiguous or incomplete metadata remain unresolved. Standalone RISC-V PC-relative HI/LO relocations are never treated as ordinary scalar relocations. Relocation-covered or runtime-populated pointer slots, other narrow loads, floating-point loads, and unknown call effects remain unresolved. `JALR` target resolution retains the existing known-base, low-bit-clear, executable-target checks.

The Zbb `CLZ`, `CTZ`, and `CPOP` transfers propagate only a proven same-space source value (or architectural `x0`). RV64 `CLZW`, `CTZW`, and `CPOPW` operate on the low word; their count results are zero-extended because the result range is at most 32. The decoder's unary register effects and XLEN are checked before retaining the result for later address arithmetic. Mapped results receive a reference at the source operand; unknown inputs and malformed effects invalidate the destination fact.

Zba `SH1ADD`/`SH2ADD`/`SH3ADD` and their `.UW` forms propagate when both source values are proven; `.UW` zero-extends the low 32 bits of `rs1` before shifting, and sums wrap at XLEN. `ADD.UW` and `SLLI.UW` also propagate for RV64 with their zero-extension and encoded shift semantics. Producer provenance includes contributing input chains.

The RISC-V M-extension `MUL` propagates the low XLEN bits of a proven register product for RV32 and RV64. RV64 `MULW` propagates the low 32-bit product sign-extended to XLEN. Zero-register inputs are exact, and result values retain both producer chains so mapped values can become immediate xrefs and continue through supported arithmetic or memory operations. High-product forms, division/remainder, unsupported or unknown operands, and other M-extension effects do not create facts. The reference cache version advances to 22 for this added propagation.

## AArch64

`MADD` and `MSUB` propagate a W/X result when all three source registers are proven in the current address space. Arithmetic wraps at the encoded width, architectural zero registers are exact, and an unknown source invalidates the destination. These instructions have no encoded address operand; their value can still resolve a later register-based memory or control reference.

`ADR` and `ADRP` operands retain their decoded address and can produce a direct immediate reference when the exact target is addressable in the instruction's image address space. For `ADRP`, that target is the decoded page base itself; the reference does not guess a later low-page offset from a possible `ADD`. The canonical decoded instruction and its resolved operand supply the target, and ordinary mapped-segment permission checks and operand-key deduplication apply. Integer `LDR` literal forms for W/X destinations and `LDRSW` resolve the signed imm19 scaled by four relative to the current instruction address (A64 has no PC bias or alignment adjustment); xref source and operand identity remain attached to the literal memory operand. SIMD/FP literal loads and `PRFM` remain unsupported. `MOVZ` and `MOVN` seed known integer values, and `MOVK` updates one 16-bit lane only when the prior destination value is known. Their mapped results receive an immediate reference at the instruction that produced that value. Immediate `ADD`/`SUB` on matching `W` registers uses 32-bit wraparound and zero-extends the result; matching `X` registers use the existing bounded 64-bit address arithmetic. Unshifted and shifted register forms propagate when both source registers hold proven values. The extended-register forms apply their encoded UXTB/UXTH/UXTW/UXTX or SXTB/SXTH/SXTW/SXTX extension and shift before addition or subtraction; W results wrap at 32 bits and X results reject overflow or underflow. Values flow across recovered basic-block edges when every predecessor is available, and at merges a value survives only when all predecessor states agree. A load or store with a tracked base resolves only to a mapped range with the required permissions. Register-offset forms also resolve when the index register is independently proven: UXTX/UXTW/SXTX/SXTW extension and the encoded element-size shift are applied at 64 bits with checked underflow and overflow. A 64-bit `LDR` may seed its destination from a readable file-backed pointer slot, or from an exact relocation/dyld fixup at that slot when the resolver yields a mapped target; unresolved runtime-populated slots remain opaque. An integer A64 `LDR` literal with an instruction-relative resolved address follows the same bounded pointer-slot rule without requiring a tracked base register; an exact relocated target or an unrelocated file-backed 64-bit value can seed a later `BR`/`BLR` target. Stack-pointer source/destination operands, invalid wide-move shifts, unknown `MOVK` inputs, indexed forms with unknown or unsupported index values, disagreeing or cyclic-incomplete inputs, and out-of-range expressions remain unresolved.

Integer A64 `LDR Wt` now also seeds a known value from an exact relocation/fixup or a readable, file-backed 32-bit pointer slot when that zero-extended value maps into the image. This applies to literal and tracked-base loads and can resolve later register-based memory or control references. The destination must be a matching W register, the full four-byte slot must be readable, and runtime-populated or unmapped values remain unresolved. `LDR Xt` retains its separate 64-bit path; narrower values and SIMD/FP loads do not seed pointers.

A64 `AND`, `ORR`, and `EOR`, plus flag-setting `ANDS`, now propagate proven values through logical-immediate bitmasks and shifted-register forms (`LSL`, `LSR`, `ASR`, and `ROR`). The pass revalidates the encoded opcode, width, operands, shift and replicated bitmask, register effects, and NZCV write for `ANDS`; instruction bytes covered by relocations are left unresolved. W results wrap to 32 bits and zero-extend, while X results retain 64 bits. The zero register supplies an exact zero input. A result is retained for later arithmetic, memory, or indirect-control resolution, and an immediate reference is emitted only when that result maps to addressable image bytes. Unknown nonzero source values and destination writes to the zero register do not produce a tracked value; BIC/ORN/EON, flag-setting aliases beyond `ANDS`, and SIMD logical instructions are not part of this transfer.

`LDRSW Xt` can seed a later pointer fact from a readable, file-backed four-byte slot when its signed 32-bit contents, sign-extended to 64 bits, map into the image. This path accepts only unrelocated bytes in a 64-bit address space; relocated or runtime-populated slots, unknown addresses, and sign-extended values outside mapped segments remain unresolved. The reference cache version advances to 25 for this added propagation.

Flag-setting `ADDS`/`SUBS` propagate the same proven GPR data result as `ADD`/`SUB` for the supported immediate, shifted-register, and extended-register operands. The data result follows the existing 32-bit wrap or checked 64-bit arithmetic rules and may feed later address propagation. This xref extension validates operand access and register read/write metadata but makes no additional claims about the produced flags or their use by conditional control flow. SP-based operands, unknown inputs, malformed effects, and unsupported shift encodings remain unresolved.

`ADC`, `ADCS`, `SBC`, and `SBCS` decode and lift their incoming NZCV.C dependency explicitly. The value expressions use `Rn + Rm + C` or `Rn - Rm - 1 + C`; `ADCS`/`SBCS` also update the full NZCV result. Xref propagation requires both source values and a known incoming carry, and discards the destination otherwise. Carry state after flag-setting forms remains unknown when an input is unknown; this implementation does not infer targets from unresolved carry.

`EXTR` propagates a value when both inputs are proven in the instruction's address space. It applies the encoded `lsb` to the concatenated high/low operands at the decoded 32- or 64-bit width, including architectural zero-register inputs, and zero-extends a W result. A mapped result receives an immediate reference at the instruction; unknown inputs remain unresolved.

Unshifted register `AND`, `ANDS`, `ORR`, and `EOR` now transform values when both operands are proven in the current address space. The architectural zero register supplies zero; W-register results truncate to 32 bits and zero-extend, while X-register results retain 64 bits. Exact mapped results receive provenance-backed references and can feed later supported operations. Shifted logical operands, SP operands, unknown inputs, and results outside mapped address space remain unresolved.

`UBFM` and `SBFM` propagate the non-wrapping `LSR`/`ASR` and `UBFX`/`SBFX` alias forms when their source is proven. Extraction uses the encoded W/X width, shift, and inclusive bit-field bounds; signed extraction extends the selected sign bit to the destination width. `BFM` propagates `BFXIL` and wrapped `BFI`/`BFC` forms when both the prior destination value and source value are proven; it preserves the untouched destination bits and handles W-register truncation. A reference is emitted only when the exact result maps into the image, and the result remains available to later supported arithmetic. Unknown source/destination values and unmodeled data-processing forms remain unresolved.

`CSEL`, `CSINC`, `CSINV`, and `CSNEG` evaluate the 14 standard conditional predicates and `AL` when NZCV is proven earlier in the same basic block by supported `ADDS`/`SUBS`, `ANDS`, or `CCMP`/`CCMN` operations; reserved `NV` remains unresolved. Arithmetic flags use the decoded W/X width; conditional compares either calculate their result flags or install the encoded fallback NZCV nibble. The false-arm transformation is applied at the encoded width, including W truncation. The decoder represents the `CINC`, `CINV`, and `CNEG` aliases as their canonical CS* opcode with the original encoded condition and both register operands (the two sources are equal for these aliases); analysis uses that detail directly and does not derive an outcome from the alias spelling. Unknown incoming flags, unsupported flag writers, calls, and CFG joins do not contribute flag facts. Equal proven alternatives remain safe even when their condition is unknown. A propagated value can resolve later register-based memory references, while the select itself has no encoded address operand to reference.

An integer `LDP` through a proven base resolves the pair's memory reference and can seed each W/X destination independently from its corresponding readable file-backed pointer slot or exact relocation/fixup. Each slot is range-checked separately, destinations must match the decoded width and register-write set, and relocated or file-backed values seed a register only when the result is mapped. The second slot address uses checked addition. Unknown values, invalid destinations, unreadable slots, and unmapped targets remain unresolved. The reference cache version advances to 29 for paired-load pointer propagation.

Logical-immediate `AND`, `ORR`, `EOR`, and `ANDS` also propagate when the source register is proven. The decoder's expanded logical mask is applied at the encoded W/X width, then the existing mapped-image check determines whether the immediate operand contributes a reference and the destination constant remains available to later supported operations.

## A32 and Thumb

PC-relative `LDR` and related instructions with a decoded absolute effective address produce data references. This includes Thumb literal loads, whose decoder aligns the PC base as required by the encoding. Across recovered basic-block edges, A32 `ADD`/`SUB` immediate address formation from PC (PC+8) and Thumb `ADR` seed a register value; immediate `ADD`/`SUB` can carry that value forward. At joins, a value survives only when every predecessor provides the same address. Calls, cyclic or incomplete predecessor graphs, and A32/Thumb state changes clear facts. Loads and stores through a tracked base resolve only when the full access range is mapped with the needed permissions. Immediate and statically shifted register offsets (`LSL`, `LSR`, `ASR`, and nonzero `ROR`) are evaluated at 32 bits; pre-index and post-index effective addresses are distinguished, and a proven writeback updates the tracked base for following instructions. Dynamic shifts, `RRX` without a proven carry, multi-register transfers, and arbitrary arithmetic remain unsupported.

Unconditional A32/Thumb `MOV`, `MVN`, `AND`, `EOR`, `ORR`, `BIC`, `ADD`, `SUB`, and `RSB` data-processing forms now propagate a destination when their source values are proven. Operand2 may be an immediate, a proven GPR, or a statically/proven-register shifted GPR using `LSL`, `LSR`, `ASR`, `ROR`, or `RRX`; each shift is evaluated with the architecture's 32-bit rules. `RRX` and carry-dependent `ADC`/`SBC`/`RSC` resolve only when carry and all source values are proven. Predicated writes invalidate their destination facts instead of being assumed to execute, while their encoded immediate references remain available. The resulting address definitions retain the producing instruction for reference provenance. This follows the same constant-propagation approach used by Ghidra's [ARM analyzer](https://github.com/NationalSecurityAgency/ghidra/blob/master/Ghidra/Processors/ARM/src/main/java/ghidra/app/plugin/core/analysis/ArmAnalyzer.java), while HexLab additionally requires predecessor agreement and validates each target's execution-mode mapping.

In A32 data-processing operations, a decoded PC source or Operand2 PC is evaluated as the instruction address plus eight. This allows otherwise supported operations such as `MOV pc, pc` and logical/arithmetic PC writes to resolve when their other inputs are known. Thumb register reads of PC remain unresolved here because their alignment and bias depend on the instruction encoding.

Thumb-2 `MOVW` seeds a 32-bit register value from its exact 16-bit immediate, and `MOVT` replaces the high half only when the destination's prior low half is proven. These values can feed later mapped memory references, arithmetic, or indirect control transfers across recovered CFG edges. The decoder's register effects and known-true predicate are checked; unknown/false IT execution never fabricates a value, and relocation-covered instructions invalidate their destination without interpreting encoded relocation bits. The reference cache version advances to 17 for this propagation change.

Known register-derived writes to PC now resolve control references for A32/Thumb `BX`/`BLX`, data-processing writes such as `MOV`/`MVN` and supported arithmetic/logic operations, `LDR pc`, and `LDM`/Thumb `POP` when the loaded PC slot is statically available. For data-processing PC writes, an unknown A32 condition or Thumb IT predicate does not suppress the possible target xref when the predicate metadata is valid and the pre-instruction operands (including carry where needed) uniquely determine the destination. That uncertain instruction never advances the register facts used on later paths. `ArmExchange` and target-context metadata select Thumb versus A32 and apply the corresponding alignment before checking executable mappings. Exchange targets with low bits `10` are left unresolved because that A32 target encoding is unpredictable. This includes bit-zero interworking for valid exchange/load/ALU writes and Thumb-state retention for non-exchange writes. Resolved control references retain the proven target mode in the reference payload, and the desktop reference list shows `[A32]` or `[Thumb]`; following the address uses the image's validated target context. Reference payload v16 adds this field and rekeys older cached records on load. LDM/POP references attach to the register-list operand containing PC. The analyzer does not read relocation-covered pointer slots or infer values through runtime memory or unresolved register inputs.

## MIPS32

The analyzer tracks address values formed by `LUI`, followed by immediate `ADDI`, `ADDIU`, or `ORI`, and by 32-bit `ADD`/`ADDU`/`SUB`/`SUBU` and `AND`/`OR`/`XOR`/`NOR` when both inputs are proven. Fixed `SLL`/`SRL`/`SRA` and variable `SLLV`/`SRLV`/`SRAV` also transform proven register values; fixed amounts use the decoded immediate, variable amounts use the low five bits of the proven amount register, and arithmetic right shifts preserve the sign bit. Results follow MIPS32 32-bit register semantics. Trapping `ADD`/`SUB` results are retained only when signed overflow is ruled out; unsigned variants wrap at 32 bits. Logical results are truncated to the MIPS32 register width. Facts flow across recovered basic-block edges when every predecessor is known, and a register survives a merge only when all predecessor values agree. Loads and stores through that base plus the decoded displacement produce references only when the full data range is mapped with suitable read/write permission. An `LW` may also seed its destination from a full pointer stored in a readable, file-backed slot when the loaded value maps into the image; relocation-covered and runtime-populated slots are not interpreted. GPR zero is never treated as a writable address register. Proven, aligned `JR`/`JALR` values resolve only inside executable mapped segments. Cyclic or incomplete predecessor graphs do not contribute speculative incoming values; unsupported register-indirect control flow preserves its typed expression.

`CLZ` and `CLO` propagate a count from a proven MIPS32 source register through the shared instruction-effect evaluator. `$zero` is treated as a zero input, the destination must be writable, and the resulting value can feed later supported arithmetic or memory analysis; a mapped result also receives an immediate xref. Unknown inputs, invalid decoded effects, and other count/leading-zero forms remain unresolved.

`SLT`/`SLTU` and `SLTI`/`SLTIU` propagate exact zero-or-one results when their register inputs are proven. The shared evaluators validate instruction effects and implement signed comparisons versus unsigned comparisons with the sign-extended immediate required by MIPS32. `$zero` inputs are known zero. Result facts can feed later arithmetic; malformed effects and unknown register inputs invalidate the destination. The reference cache version advances to 24 for this added propagation.

Release 2 `EXT` zero-extends a proven 32-bit source slice into the destination, and `INS` replaces a proven destination bit range with bits from a proven source. Both require valid decoded position/size fields and consistent register/effect metadata; `INS` also requires a known prior destination value. A resulting mapped address receives a reference at the decoded size operand and continues through bounded CFG propagation with its producer instructions retained. Unknown input values, invalid ranges, and targets outside mapped image segments do not create references. These word forms are handled only in MIPS32 mode; MIPS64's shared opcodes retain their separate GPR-width semantics.

## MIPS64

MIPS64 address facts use the decoded 64-bit GPR width. `LUI` sign-extends its 32-bit result; `DADDIU` and `ORI` extend or combine a known base, and `DSLL`/`DSLL32`, `DSRL`/`DSRL32`, `DSRA`/`DSRA32`, and their variable-shift forms transform known values with 64-bit register semantics. Logical left shifts truncate to the GPR width, logical right shifts zero-fill, arithmetic right shifts preserve the sign bit, and `DROTR`/`DROTR32`/`DROTRV` rotate within 64 bits. The word-width `ROTR`/`ROTRV` forms rotate the low 32 bits and sign-extend the result to the 64-bit GPR, matching the architectural word-result behavior. Variable shift counts are taken from the low six bits for doubleword operations and low five bits for word operations; unknown counts invalidate the destination fact. Register `AND`/`OR`/`XOR`/`NOR` combine proven 64-bit inputs. The word-width `ADDI`/`ADDIU` forms are propagated only from sign-extended 32-bit inputs; `ADDI` must not overflow and `ADDIU` wraps at 32 bits before sign extension. `LD` and `SD` base-plus-displacement operands resolve only when the full 8-byte access has the required mapping and permission. A full-width `LD` may seed its destination from a readable, file-backed pointer slot with no overlapping relocation. A `LWU` may also seed its 64-bit destination from a readable, file-backed 32-bit pointer slot with no overlapping relocation; the loaded value is zero-extended and must point into a mapped segment. This covers valid low-address 32-bit pointer values without treating every 32-bit load as a pointer. `JR`/`JALR` resolve only when the tracked value is four-byte aligned and points into an executable mapped segment. MIPS64 width is never inferred from an MIPS32 fact; unsupported arithmetic, unknown call effects, and conflicting or incomplete CFG inputs discard facts.

`DCLZ` and `DCLO` propagate exact 64-bit leading-zero and leading-one counts from a proven same-space source register; `$zero` is an exact zero input. The processor evaluator validates the decoded SPECIAL2 operand/effect shape, and the result remains available to later supported arithmetic and memory analysis. A mapped count result receives an immediate xref at the source operand; unknown sources and malformed effects invalidate the destination.

MIPS64 `SLL`/`SRL`/`SRA` and their variable-count forms now propagate the
architecturally sign-extended word result. The operation reads the low 32 bits,
uses a five-bit shift count, applies logical or arithmetic shifting at 32 bits,
then sign-extends the result to the 64-bit GPR. Variable counts require a
proven register value; `$zero` is exact zero. The resulting reference is kept
only when the sign-extended value maps into the image. This does not extend
word-shift behavior to MIPS32 or infer any unknown input values. The semantics
follow the [MIPS64 Instruction Set Reference](https://s3-eu-west-1.amazonaws.com/downloads-mips/documents/MIPS_Architecture_MIPS64_InstructionSet_%20AFP_P_MD00087_06.05.pdf).

SPECIAL2 `MUL` now propagates a known low-word product into its destination as a sign-extended 64-bit value. Both operands must be known in the current address space, with `$zero` accepted as zero. A mapped result gets an immediate reference at the source operand; the destination remains available to later supported arithmetic and memory operations. `MUL`'s architecturally unpredictable HI/LO outputs are not used as facts. This models the defined GPR result only and does not infer addresses from unknown input values.

`DEXT`/`DEXTM`/`DEXTU` zero-extend a proven source bit range, and `DINS`/`DINSM`/`DINSU` insert a proven source range into a proven prior destination value. Position and size use the decoded Release 2 fields; malformed operand/effect metadata, unknown source values, or unknown insertion destinations invalidate the result. A mapped result can produce an immediate data reference, and the result continues through the existing CFG value propagation. The bitfield operation does not infer a value for unavailable incoming register state.

The MIPS64 bitfield transfer requires the exact encoded position/size field
widths and byte coordinates, a four-byte fallthrough instruction with no
memory effects, and no relocation overlapping the instruction bytes. A
relocation-covered instruction is not interpreted from its pre-relocation
immediate fields, even if those fields otherwise form a valid bit range.

## PowerPC

PPC32/PPC64 facts use the active mode's exact GPR and address width. `ADDI`/`ADDIS` form an address from a tracked base or the architectural zero base; `ORI`/`ORIS` combine an immediate with a tracked source. Register `ADD` and `SUBF` propagate only when both full-width inputs are known in the current address space; results use the active 32- or 64-bit wrap semantics (`SUBF` computes RB minus RA). Values flow through the existing bounded CFG must-analysis and survive joins only when predecessor values agree. D-form and indexed memory operands use the decoded base, index, scale, and signed displacement; update forms write the proven effective address back to the base register. Memory references require the full operand data width to be mapped with the required permission. A full-width `LWZ` in PPC32 or `LD` in PPC64 may seed the destination from a readable, file-backed pointer slot when the target maps into the image and no relocation covers the slot. Narrow loads, indexed expressions with an unknown register, mismatched widths, relocation-covered slots, calls, and disagreeing control-flow values remain unresolved.

PPC64 `RLDICL`, `RLDICR`, and `RLDIC` (including record forms) propagate a proven 64-bit source through the encoded rotate-left and circular PowerPC-numbered bit mask. `RLDCL` and `RLDCR` (including record forms) use the low six bits of a proven same-space count register and the decoder-normalized circular mask (`MB..63` or `0..ME`). The result is retained for subsequent supported address arithmetic and memory operands; when it maps into the image, an address reference is attributed to the shift operand and includes the source producer chain. Unknown or cross-space source/count facts, malformed effects, and results outside mapped segments do not create address references. PPC64 insert (`RLDIMI`) remains unresolved; selected PPC32 word forms are covered separately below.

`CNTLZW` propagates the leading-zero count of a proven source GPR in PPC32 and PPC64; PPC64 `CNTLZD` propagates the 64-bit count. Record forms are accepted only when their decoded XER/CR0 effects match the instruction form, but only the GPR result is retained. The result may feed later address arithmetic, and a mapped result receives an immediate xref. Unknown sources and malformed effect metadata invalidate the destination. The reference cache version advances to 26 for this propagation.

`EXTSB` and `EXTSH` propagate a proven source through sign extension to the active GPR width; PPC64 `EXTSW` sign-extends the low word. The shared instruction evaluator validates the source width and decoded result behavior, while this xref path also checks exact GPR/XER/CR0 effects for record forms and retains only their GPR data result. A mapped result receives an immediate xref and can feed later supported operations. Unknown sources, unsupported widths, and mismatched effects invalidate the destination. The reference cache version advances to 27.

`POPCNTB` propagates a per-byte population count in the active GPR width; `POPCNTW` counts the low word, and PPC64 `POPCNTD` counts the full doubleword. The decoded source width and GPR read/write effects are checked before evaluation. Proven results can feed later supported arithmetic and mapped values receive an immediate xref. Unknown sources and malformed effects invalidate the destination. The reference cache version advances to 28.

PPC32 `RLWINM` (including its record form) propagates a proven GPR through the 32-bit rotate-left and PowerPC-numbered inclusive mask. Wrapped mask ranges retain their architectural wrap across bit 31 to bit 0. The result is zero-extended to the PPC32 address width, retained for later supported dataflow, and receives an immediate reference at the shift operand when it maps into the image. `RLWNM` (including its record form) propagates when both the source and shift GPRs are proven in the current address space; the low five shift bits and encoded inclusive mask are applied at 32 bits. `RLWIMI` (including its record form) propagates when both the prior destination and source are proven in the current address space. It rotates the source left by the encoded five-bit amount, inserts only the inclusive mask range into the prior destination, and retains the merged value for later supported dataflow. PPC64 `RLDIMI` (including its record form) now does the same with the six-bit rotation and wrapped 64-bit inclusive mask. Mapped results receive an immediate reference at the shift operand. Unknown prior destination/source values, malformed immediate ranges, and cross-space facts discard the result. PPC64 word forms remain unresolved.

## NMOS 6502

Absolute unindexed memory operands produce read, write, or read/write references according to the instruction effect. Indexed expressions remain unresolved when the effective address depends on runtime register values. `JMP ($addr)` reads its two-byte pointer from readable, file-backed memory only when neither byte overlaps relocation data; the decoded reference points to the pointer slot, while the jump reference points to the destination only when it is mapped executable code. The NMOS page-boundary behavior is modeled: a pointer at `$xxFF` reads its high byte from `$xx00`. `JMP` and `JSR` absolute forms retain their decoded direct targets. Runtime-written pointers, relocation-covered pointer bytes, unmapped operands, and non-executable destinations remain unresolved.

Within a recovered basic block, immediate `LDX`/`LDY` values and known `TAX`/`TAY`/`TXA`/`TYA` transfers propagate through `INX`/`DEX`/`INY`/`DEY`. Absolute indexed memory operands resolve when the corresponding X or Y value is known; 16-bit effective-address wrap is applied. Zero-page indexed operands also resolve from a known X/Y value, with the required 8-bit zero-page wrap. The `(zp,X)` and `(zp),Y` data modes resolve when the selected index is known and both zero-page pointer bytes are initialized, readable, non-writable, and uncovered by relocations; the pointer high-byte fetch wraps within zero page, and `(zp),Y` then adds Y with 16-bit wrap. The resulting access still has to pass ordinary mapping and permission checks, and the known index instruction is retained as producer provenance. Writable/runtime pointer cells, relocation-covered bytes, memory-loaded indexes, and unresolved pointer bytes remain unresolved. Facts reset at block boundaries.

## Conservative boundaries

For all supported architecture families, permission failures and incomplete target ranges remain unresolved. Unsupported addressing modes, runtime-dependent registers, and unresolved pointer values retain their expression where available instead of generating speculative incoming references.

## AArch64 unsigned and signed bitfield values

The AArch64 reference pass propagates `UBFM` and `SBFM` when the source register is already proven and the decoded operand widths, bit positions, and register effects match the instruction encoding. This covers the encoded forms used for `UBFX`, `UBFIZ`, `LSR`, `LSL`, `SBFX`, `SBFIZ`, `ASR`, and sign-extension aliases. The result is truncated to the destination width; a 32-bit result is zero-extended as a W-register write. Mapped results can feed later arithmetic, memory accesses, and indirect branches. Unknown source values or mismatched instruction effects invalidate the destination instead of producing a reference. `BFM` insertions that depend on a previous destination value are not included in this transfer. The bitfield behavior follows Arm's [A64 UBFM and SBFM reference](https://documentation-service.arm.com/static/6245c734b059dc5ff9a8bdab).

## Querying data objects

`ReferenceIndex::incoming_range` and `hexlab_cli project references --direction incoming --size N` return references whose numeric target or resolved association lies within the half-open VA range `[--at, --at + N)`. This lets a data object query find references to interior bytes, such as a field or a string element, while retaining normal reference-kind and provenance details. Range queries are bounded to one address space and reject empty or overflowing ranges; outgoing queries remain instruction-address based. Range pages de-duplicate overlapping targets with a row-index bitmap instead of a match-sized temporary, so the de-duplication workspace is capped at about 489 KiB by the four-million-reference index limit; returned rows remain capped at 4,096 and ordered by the reference index's stable row order. The index stays immutable and range queries add no persistent result cache; project consumers keep their existing `AnalysisKey` checks for input, byte revision, and decision revision before using an index.

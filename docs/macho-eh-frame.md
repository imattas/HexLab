# Mach-O `.eh_frame` function roots

For linked, little-endian 64-bit x86_64 and arm64 images, the loader recognizes a bounded subset of `__eh_frame`: CIE versions 1, 3, and 4. Version 4 must declare an 8-byte address size and zero segment-selector size. `z` augmentations accept the `P`, `L`, and `R` payload fields plus the payload-free `S` signal-frame marker, in any specified order; unknown augmentation characters remain unsupported. Pointers use absolute, PC-relative, or aligned application with `absptr`, ULEB128, SLEB128, and fixed 2, 4, or 8-byte signed/unsigned formats. `DW_EH_PE_aligned` is accepted only with `absptr`; its pointer field advances to the next 8-byte aligned address using the section virtual address, with padding and field bounds checked. A shared bounded scalar decoder reads fixed-width and LEB values; PC-relative initial locations add signed or unsigned deltas to the address of the encoded field with checked overflow/underflow. The FDE address range uses only the format nibble from the CIE encoding, without applying the initial-location relocation mode, as specified by DWARF. Each retained function preserves the CIE pointer encoding alongside its bounded CIE/FDE instruction streams and exception metadata in `MachOMetadata::eh_frame_functions`; its start is added to the existing function-start root list, so automatic function recovery can use it alongside compact-unwind entries.

The parser bounds each record and augmentation against the section, limits section input to 64 MiB, checks arithmetic and requires the full FDE range to map to initialized executable bytes. It requires even an empty FDE augmentation-length field for `z`-augmented CIEs and rejects overflowing ten-byte SLEB encodings. Unsupported CIE augmentation or pointer encodings are skipped, including indirect pointers and text/data/function-relative application modes. Runtime evaluation supports `DW_CFA_def_cfa`, CFA register/offset updates, location advances, register offset/value-offset/same/undefined/register rules, restore rules, and bounded `DW_CFA_remember_state`/`DW_CFA_restore_state` nesting (maximum depth 1024) for the supported nonvolatile registers: x86_64 callee-saved registers, arm64 X19-X30 and D8-D15. `DW_CFA_val_offset` and `DW_CFA_val_offset_sf` compute the saved register value directly from the CFA and therefore do not read stack memory.

The evaluator also accepts GCC's legacy `DW_CFA_GNU_negative_offset_extended` rule. Its register and ULEB factor are decoded with overflow checks; the rule records the negated, data-alignment-scaled offset. This is useful for older GCC CFI and does not change the supported register set.

On arm64, `DW_CFA_AARCH64_negate_ra_state` toggles the CFI return-address-sign state. The result exposes `return_address_signed` for the selected PC, including state changes in the CIE and FDE programs. The evaluator reports the state and leaves the recovered PC raw; it does not perform pointer authentication. The opcode is rejected on other architectures because the same byte value means GNU `window_save` there. The deprecated `_with_pc` form and AArch64 `set_ra_state` remain unsupported.

On x86_64, `DW_CFA_GNU_args_size` records its bounded ULEB value in `MachOUnwindResult::gnu_args_size` for the selected PC. This metadata does not adjust the recovered caller stack pointer; the evaluator uses the CFA for that value. The opcode is rejected on other architectures.

`DW_CFA_def_cfa_expression` is supported in addition to register-based CFA definitions. Its expression block is limited to 4096 bytes and 64 operations, uses a maximum 16-value stack, and supports register-relative `DW_OP_bregN`/`DW_OP_bregx`, literals, `DW_OP_constu`/`DW_OP_consts`, fixed-width `DW_OP_const1u/s`, `DW_OP_const2u/s`, `DW_OP_const4u/s`, and `DW_OP_const8u/s`, `DW_OP_plus`/`DW_OP_minus`, `DW_OP_plus_uconst`, and 8-byte `DW_OP_deref`. Fixed-width constants are decoded little-endian, and signed forms are sign-extended to the 64-bit target width. `DW_OP_stack_value` and `DW_OP_implicit_value` are decoded for saved-register rules; implicit values are limited to eight bytes. Truncated operands fail as malformed expressions; unsupported operators still fail closed. It computes the CFA directly from the current register context; `DW_OP_call_frame_cfa` is rejected because it would be circular. Register-based `DW_CFA_def_cfa_register` and offset updates are rejected when the active CFA is expression-based, until another full register-based CFA definition replaces it.

`DW_CFA_expression` and `DW_CFA_val_expression` are supported for saved-register rules using the same bounded operator subset, including fixed-width constants. Their expression blocks cannot use `DW_OP_call_frame_cfa`; the rule's target register must map to the exposed x86_64 or arm64 unwind context. Location expressions read the saved value from the resulting address unless the expression ends with a value description. They may also end in `DW_OP_reg0` through `DW_OP_reg31` or `DW_OP_regx`; in that form, the source register's current context value is copied directly to the caller rule without reading memory. Register-location operators are accepted only as the final expression result (or when duplicated, picked, or dropped before that result); arithmetic use is rejected. The source register must map to a register exposed by the unwind context. `DW_CFA_val_expression` does not accept a register-location result. `DW_CFA_def_cfa_expression` still requires an address result and rejects both value descriptions and register locations. `MachOUnwindResult::expression_rules_evaluated` reports how many saved-register expression rules were applied. Unknown registers, malformed stacks, truncated operands, arithmetic overflow, memory-read failures, and unsupported expression operators return explicit errors. The CIE and FDE instruction byte streams remain retained on `MachOEhFrameFunction` with the FDE record file offset, so expression bytes and their program location can be recovered from the original encoded instruction stream. This subset does not implement pieces, TLS, or arbitrary DWARF expression operations. State-stack underflow is malformed. The evaluator restores caller PC and SP from the return-address rule and CFA.

For the `P`, `L`, and `R` augmentation fields, indirect, text/data/function-relative and unknown EH pointer encodings remain unsupported; supported pointer forms are absolute `absptr`, `uleb128`, `sleb128`, `udata2/4/8`, and `sdata2/4/8`, with absolute, PC-relative, or aligned application. Unsupported personality-pointer encodings mark the CIE unsupported and do not produce function roots; unsupported FDE LSDA-pointer encodings leave the FDE root intact but mark its LSDA incomplete. The loader associates validated personality and LSDA addresses with each FDE. It parses the LSDA LPStart, optional type-table offset and encoding, call-site encoding, and bounded call-site rows from the initialized containing section. Each row retains its function-relative start/length and landing-pad offset plus its action index, with ranges and landing pads checked against executable image bytes.

Action records reachable from a nonzero call-site action index are decoded as bounded SLEB128 type-filter/displacement pairs. The parser follows self-relative links, retains shared records once, records the per-call-site chain order, rejects cycles and targets outside the action-table extent, and caps each chain at 4,096 records and each LSDA at 65,536 distinct action records. The table extent ends at the bounded type-table base when present, or at the end of the containing initialized section otherwise. A personality symbol is associated with the FDE when its resolved address matches a defined Mach-O symbol. Only the exact Itanium C++ `__gxx_personality_v0` spelling (with the Mach-O external-name prefix removed for classification) enables type-table interpretation; the loader preserves the symbol spelling and never calls the personality routine.

For that recognized personality, positive action filters index fixed-width reverse type-table entries when the encoding is absolute or PC-relative and uses `absptr`, `udata2/4/8`, or `sdata2/4/8`. Each referenced entry records its index, LSDA byte offset, encoding and resolved pointer. Null entries are retained as catch-all type pointers; nonnull pointers are accepted only when they map to initialized readable image bytes. `target_state` distinguishes a null catch-all, a readable pointer, an exact defined RTTI symbol match, ambiguous aliases and an invalid pointer. When a pointer exactly matches a defined Mach-O symbol using the Itanium `_ZTI` prefix (after removing Mach-O's external-name underscore), up to 16 candidate RTTI symbol names are attached to that entry. Multiple aliases, or more than 16 candidates, are marked ambiguous; the loader does not infer a single type name from them. This verifies the pointer against the image mapping and symbol table, but does not parse the RTTI object's class hierarchy. Entry indexes are limited to 65,536, and the action records must end before the indexed type-table extent. A zero action filter remains a cleanup action. Negative exception-specification filters, variable-width or indirect encodings, non-C++/unresolved personalities, RTTI object interpretation and subtype matching remain unsupported and leave `lsda_complete` false. If an unsupported encoding is encountered partway through an LSDA, its decoded rows, actions and type entries are discarded together; the LSDA section ordinal and slice-relative file offset remain as source provenance. Malformed encodings fail the containing metadata load instead of publishing a partial image. This is structural metadata only; no target code is executed.

The decoded rows, action chains, type-info pointer records, resolved personality-symbol metadata, and containing LSDA section/file offset live in `MachOMetadata::eh_frame_functions` on the loaded image. The Mach-O metadata browser exposes one row per FDE and separate rows for its personality field, call sites, action records, and type-info entries. Each row retains its owning FDE index. The source-derived model records whether a `P` field was present, its EH pointer encoding byte, and the global file offset and length of the encoded field. If the encoding is unsupported, it still retains and navigates to the encoding byte; the pointer span is extended when decoding succeeds. FDE and personality rows distinguish an absent field from a present but unclassified or unresolved personality. Call-site rows show function-relative starts and landing-pad offsets and list up to eight reachable action-record offsets; the complete chain length remains visible. Personality recognition, symbol names, and RTTI pointer states are evidence only; the browser does not interpret RTTI hierarchies or decide which catch clause handles an exception.

Mach-O metadata is source-backed project state: the project retains the original input bytes, and reopening it reparses the loader metadata from those bytes. This makes the LSDA/personality rows reproducible without a second, independently versioned copy of derived loader records in the project database. The decoded metadata remains available only while the corresponding loaded image snapshot is retained.

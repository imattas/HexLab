# Mach-O compact unwind roots

HexLab reads the version 1 `__TEXT,__unwind_info` compact-unwind index for linked, little-endian 64-bit x86_64 and arm64 images. It recognizes regular and compressed second-level pages, resolves compressed-page offsets relative to their indexed function base and reads both common and page-local encoding arrays, checks index/page extents against the section, validates ordered function offsets and their executable initialized mappings, and preserves the raw encoding word and source offset in `MachOMetadata::compact_unwind_functions`.

Each validated function entry is also added to the existing Mach-O function-start collection. Function recovery and reachable analysis therefore treat compact-unwind entries as linker-declared roots without needing to understand the platform’s register-save encoding. Compressed entries resolve their common-encoding table index; regular entries preserve their inline encoding.

The runtime API in `hexlab/loaders/macho_unwind.hpp` evaluates any PC inside a proven indexed interval for x86_64 RBP, immediate-stack, and indirect-stack recipes, and arm64 frame and frameless recipes, including encoded integer and D-register saves. It also evaluates the arm64e authenticated-frame recipe using the encoded `pacibsppc` instruction offset, and reports whether that instruction has executed in `return_address_signed`; it does not authenticate or strip pointer bits. The authenticated recipe is accepted only for an ARM64E slice and only when its PAC instruction offset lies inside the proven function interval. It uses a caller-provided memory reader and returns a recovered caller context and CFA. Recipe stack slots request 8-byte reads; CFI expressions can request smaller widths through `deref_size`. x86_64 indirect-stack recipes validate the saved-register permutation and immediate range within its function interval when loading; at runtime they read the encoded prologue offset through the bounded memory callback, require it to identify the immediate in `subq $imm32, %rsp`, and compute the frame extent from that immediate plus the encoded push adjustment. The offset and 7-byte instruction read must remain inside the proven function interval; the resulting frame size must be aligned, exceed 2048 bytes, and contain all saved registers and the return address. Arm64 DWARF-mode entries bind the low-24-bit __eh_frame-relative offset to one exact decoded FDE. The compact range start and current PC must lie within that FDE, and both record sources must lie in initialized sections of the selected slice. The nearest following entry in the same compact section also bounds PC; for a terminal entry, the exact FDE end supplies the bound. The bounded CIE/FDE interpreter supplies caller state and reports signed return addresses without authentication; the result keeps the compact encoding and FDE source offset. x86_64 DWARF entries retain the existing PC-range FDE lookup. The [LLVM compact-unwind encoding header](https://github.com/llvm/llvm-project/blob/main/libunwind/include/mach-o/compact_unwind_encoding.h) defines the offset field. This API does not merge relocatable object-file unwind contributions, perform personality dispatch, or support 32-bit/big-endian compact-unwind parsing. Images without this section continue through their existing symbols and `LC_FUNCTION_STARTS` roots. Malformed declared compact-unwind data fails the load instead of producing partial roots.

The `__eh_frame` expression evaluator also supports bounded scalar DWARF stack and arithmetic operations commonly needed by CFA and register expressions: `dup`, `drop`, `over`, `pick`, `swap`, `rot`; `abs`, `neg`, `not`; bitwise `and/or/xor`; signed `div/mod`; fixed-width `plus/minus/mul`; `shl/shr/shra`; equality and signed relational comparisons; and `deref_size` widths from one through eight bytes. `DW_OP_deref` continues to request an eight-byte read. All reads go through the caller callback, which can receive widths 1..8 for `deref_size`; no direct process-memory access occurs. Expressions remain bounded to 64 operations and a 16-value stack. Division by zero, signed division overflow, unrepresentable `abs`/`neg`, invalid shifts, underflow, truncated operands, and failed memory reads are errors. Address arithmetic wraps modulo 2^64; this is an unwind-expression subset, not a general DWARF evaluator. Branches, register-location results, pieces, implicit values, typed operations, and calls remain unsupported. Opcode semantics follow the [DWARF Version 4 standard](https://dwarfstd.org/doc/DWARF4.pdf).


The analysis layer also retains each validated compact-unwind index interval as a candidate function extent. The interval runs from an entry to the next compact-unwind entry, or to the following top-level index row for the last entry on a page. Before it limits CFG ownership, recovery rechecks that the complete interval lies in initialized executable bytes in one segment. A stronger extent already attached to the same start takes precedence; a conflicting known function start suppresses the compact extent. These boundaries prevent adjacent compact-indexed functions from being merged during fallthrough recovery. They remain linker index ranges rather than proof that every byte is instruction data, and do not supply boundaries for images that lack compact-unwind entries.

# Desktop workspace persistence

HexLab stores the desktop frame's normal position and size, maximized state, and wxAUI pane perspective in the per-user wxWidgets configuration under the `Desktop` group. The perspective is restored after the panes are created. `View > Reset Layout` returns to the built-in pane arrangement; closing afterward saves that arrangement as the next startup layout.

Saved geometry is accepted only when its dimensions meet the application's minimum and part of the frame remains visible on a currently attached display. Invalid or off-screen geometry falls back to the standard startup size. A missing or invalid AUI perspective falls back to the current built-in perspective. The saved perspective is capped at 64 KiB.

Open saved projects and imported binary tabs are persisted separately under the per-user `Desktop/Session` configuration group. At most 32 entries are retained, with each path capped at 32,768 characters and each encoded loader recipe capped at 64 KiB. Saved project read-only/collaborative mode is retained. Binary tabs restore only when their source path and durable loader recipe are both present; raw mappings, concrete format choices, Mach-O selection, PDB binding, and PE runtime architecture come from that recipe rather than guessed defaults. Projects that cannot be read follow the regular asynchronous project-open error path. Missing paths, malformed records, plugin-backed recipes, and entries without enough durable source information are skipped safely. The previously active persisted tab is selected after restored opens finish. Transient pages and unsupported unsaved documents are not persisted. This session record is independent of the wxAUI perspective and frame geometry settings.

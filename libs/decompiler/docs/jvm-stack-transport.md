# JVM operand stack across basic blocks

The JVM lifter infers operand-stack shapes over the original CFG before emitting expressions. A worklist starts with the empty method-entry stack and the single opaque reference at each exceptional handler entry. Ordinary predecessors propagate exact logical stack shapes until no unresolved reachable entry remains. Every subsequent input, including a loop backedge, must match the established height and primitive value categories. Block order and expression pointer identity do not determine acceptance.

Distinct `int`, `long`, `float`, and `double` values can now meet at a join or loop header. Each outgoing logical stack slot receives an explicit versioned definition in the predecessor. A block with multiple distinct ordinary predecessor blocks receives a `LiftedBlock::Phi` per incoming slot; each input identifies its predecessor and that predecessor's output version. A block with one predecessor reads its output versions directly. Repeated switch/conditional edges from one predecessor count as one phi input. Values below a branch condition or switch selector remain available to the chosen successor.

Stack registers use the dedicated `RegisterBank::jvm_stack` bank, displayed as `jvm_stack_N`. Definitions before a terminal branch and phi inputs refer to explicit versions, preserving old values through swaps and other stack permutations. Local loads also define a stack value at the load instruction, so later stores or `iinc` cannot change an already-loaded value. The generic `to_ssa` pass preserves this bank's existing versions and phis while continuing to construct SSA for locals and memory. This bank is reserved for stack SSA emitted by the JVM lifter; callers must not treat it as an unversioned architectural register bank.

Category-2 values (`long` and `double`) remain one logical expression, register, and phi slot. They count as two physical slots when checking `Code.max_stack`. The existing category-checked `pop2`, `dup*`, `dup2*`, and `swap` transfer rules run in both shape inference and expression emission. The two passes share the opcode transfer implementation and must agree on every exit shape. Local accesses also respect `Code.max_locals` when matching method metadata is available. The common IR limits the operand stack to 256 logical values and local register indexes to 0?255; larger methods fail explicitly.

## Exact reference transport from verifier frames

The lifter consumes the [expanded StackMapTable model](../../../docs/jvm-stack-map-tables.md) as a constraint at every decoded block entry that has an explicit frame. Each such frame must match the inferred logical stack height and value categories, remain within `max_stack`/`max_locals`, and agree with any locally proven reference identities; known references must be assignable to the frame type. Reference-bearing ordinary joins and CFG backedge targets additionally require an explicit frame at the exact method-relative bytecode offset and fully proven reference identities for stack values and reference locals. An absent table, an explicitly empty table, or a missing target frame supplies no such proof. Frames do not replace the existing primitive shape analysis or widen different primitive categories.

Local verification categories begin from the method descriptor's receiver and parameters, then follow typed local stores along ordinary and exceptional CFG edges. A join retains a category only when all incoming states agree; disagreement becomes unusable `Top`. Loads and `iinc` require a definitely initialized local of the exact JVM category, and long/double pairs must retain their second slot. Explicit StackMapTable locals constrain that incoming state and cannot initialize an otherwise unusable local. Protected throwing instructions contribute their local-category snapshot to each handler's merge.

At a handler entry, the one caught stack value receives a verifier class identity when catch clauses agree or the optional loader-qualified `JvmMetadata::known_hierarchy` graph proves their unique common ancestor; catch-all contributes `java/lang/Throwable`. Other mixed catches remain unknown. Reference joins and StackMapTable assignability use the same graph. Every node and edge carries a defining-loader identity. Duplicate class identities, cycles, incomplete ancestry, unresolved external nodes, and multiple minimal common ancestors fail closed. `invokespecial <init>` initializes aliases of `uninitializedThis` only in a constructor and only for the current class or direct superclass; the normal successor receives the current class identity. On failure, uninitialized receiver aliases in exceptional locals become unusable rather than inheriting the initialized state.

Reference identity consists of the verification kind and canonical class/array descriptor, plus the exact method-relative `new` offset for uninitialized allocations. Equivalent Class constants and descriptor-backed implicit parameters compare by their descriptor rather than constant-pool index. Null is its own identity; unknown evidence is distinct from Null. Different classes, arrays, allocation offsets, initialized/uninitialized states, or Null versus Object do not merge through assignability. `uninitialized_this` stays distinct from every allocation-site identity and initialized `this`.

A separate finite worklist propagates these identities through local loads/stores, stack permutations, constants, fields, casts, array allocation/element loads, and descriptor-typed call results. Method-entry reference locals come only from the retained implicit frame. A normal `invokespecial <init>` on a known `new` value with the exact allocation class and a void descriptor initializes that allocation's known stack/local aliases on the normal successor. Constructor chaining through `uninitialized_this`, uncertain receivers, and other unproved initialization transitions erase the affected evidence. Frames constrain incoming evidence: they never invent an identity. Top, omitted locals, changed reference types and widening erase facts before later loads. An uninitialized frame offset must resolve to one unambiguous decoded `new` inside this function.

Incoming reference identities are widened to a unique hierarchy-proven common ancestor when available; otherwise they become unknown. A reference join/backedge is accepted only when the resulting evidence is assignable to the explicit frame; accepted stack values use the same versioned definitions and phis as primitive transport. Reference values can still travel along single-predecessor chains without frames, including a handler object. Each protected throwing instruction contributes its local snapshot to the handler's finite meet. The source operand stack is discarded and replaced by exactly one caught reference. Neither exceptional-entry locals nor the caught object acquire identities from a handler frame, so a later join requiring missing identities remains unsupported.

## Conservative failures

Different stack heights, mismatched primitive categories, underflow, invalid category-2 manipulation, uninitialized or incompatible local reads, exceeded stack/local limits, unresolved CFG successor identities, StackMapTable frames outside recovered block entries, blocks outside matching method `Code`, and unreachable components without an inferable entry shape all fail closed. A handler cannot also receive an ordinary control-flow edge or serve as the method entry: exceptional entry supplies a fresh caught object rather than the predecessor's ordinary stack. Exceptional edges and handler dispatch metadata remain in the original CFG and are not normal stack-phi inputs. A nonempty stack at a function exit is rejected.

This is a structural verifier for the currently lifted subset, not a complete JVM bytecode verifier. It does not link full class hierarchies, reconstruct source-level exception structure, synthesize CFG edges, prove every local initialization rule, or establish all assignability without `known_hierarchy` metadata. Exception metadata records each protected throwing instruction and each catch clause, and pseudocode keeps those edges explicit. Memory SSA selects the pre-instruction version for array access, `arraylength`, `athrow`, and primitive constant loads. Integer division/remainder expose the zero-divisor condition; array element access exposes null and signed index-range conditions; primitive/reference array creation exposes negative-size conditions; `aastore` exposes a symbolic runtime component-type mismatch; `checkcast` exposes a symbolic type mismatch; monitor operations expose null checks and `monitorexit` also exposes symbolic ownership failure; and `athrow` records the null-to-NPE case plus propagation of the supplied exception. Runtime hierarchy/monitor predicates remain symbolic because the lifter lacks a complete runtime model at those instructions. Operations with uncertain throw timing contribute an unknown memory effect. Memory partitions remain disabled for these functions until their renamer handles exceptional inputs. Legacy `jsr`/`ret` remains unsupported. Primitive shift/bitwise transfer uses the correct int/long category, and `areturn` consumes a reference.

This integration was reviewed at source level. Builds and runtime verification remain the caller's serial follow-up.
